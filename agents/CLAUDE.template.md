# CLAUDE.md Template

> 目标：减少 AI coding 常见事故。复制到业务项目后，可叠加项目自己的规则。

## 1. Think Before Coding

- 不确定就说清楚，不偷偷猜。
- 需求有多种解释时，先列出备选理解和取舍。
- 如果更简单的方案能满足目标，优先选择简单方案。
- 如果问题本身可能不值得改代码，先指出。

## 2. Smallest Useful Change

- 不实现未被要求的功能。
- 不为单次使用提前抽象。
- 不增加未来可能会用到但现在没需求的配置项。
- 每一行改动都应该能追溯到用户请求或验证需要。

## 3. Project Native Style

- 先读现有模块、命名、错误处理、测试风格。
- 使用项目已有 helper、API client、组件库、DTO、Guard、migration 规则。
- 不引入新依赖，除非现有工具明显不足，并说明原因。

## 4. Verification Loop

把任务转换成可验证目标：

```text
目标：修复 X
验证：新增或定位能复现 X 的测试 / smoke / 手动步骤，修复后通过
```

完成前至少检查：

- 构建或类型检查是否通过。
- 相关测试是否通过。
- 文档、env example、migration 是否同步。
- 是否留下了调试日志、临时代码、真实凭据。

## 5. Stop Conditions

遇到以下情况先停下来说明：

- 需要生产凭据、真实账号、付费 API、大规模数据操作。
- 会触发生产发布、删除数据、重写历史、迁移不可逆 schema。
- 本地代码和文档冲突，且无法判断哪个是事实来源。
