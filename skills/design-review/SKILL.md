# 设计审查

## 使用时机

- 复杂方案进入 `tasks.md` 或实现前，需要做 scoped design CR。
- 用户要求评审 `plan.md`、`requirements.md`、`ui-flow.md`、原型或架构草案。
- 用户问「这个方案能不能开始写代码」「设计有没有漏」。

## 非适用场景

- 评审已写出的代码 diff → 使用 `ts-code-review`。
- 用户还在发散需求、口径未确认 → 先回到需求确认阶段。
- 发布前 Go / No-Go → 使用 `release-safety-review`。

## 必读材料

1. 目标业务项目 `README.md`、`AGENTS.md`、相关 docs。
2. `references/stages/plan.md`，按本轮风险读取相关 `references/plan/*`，不默认加载全部。
3. `references/plan/role-lens.md`。
4. 当前 feature 的 `requirements.md`、`plan.md`、`ui-flow.md`、`prototype/`（如有）。
5. 涉及 DB / 状态流 / 异步 / 全栈页面时，读取匹配 `references/scenarios/*`。

## 审查维度

### 1. 需求基线

- 是否有可观察的用户成功场景和最终消费者；高影响 `Assumed` 是否在依赖前收口。
- 非目标是否写清。
- 需求文档之间是否互相冲突。
- 是否逐条对账用户原话和最新确认业务规则；影响按钮可用、数量、额度、人工动作边界的规则是否被工程安全直觉静默覆盖。

### 2. 证据与抽象

- 是否有证据来源表；没有证据的是否标注为推断或待确认。
- 是否完成轻量领域抽象：概念、职责边界、关系、生命周期。
- 新增/改变的状态与消费路径是否有图或引用现有图；是否讲清失败、重试和实际消费者，而非仅列图名。

### 3. 工程细节

- 表 / Entity / API / DTO / ViewModel / Job 是否足够落到任务。
- 字段归属是否正确：对象自身、关系、任务上下文、计算结果。
- 当前环境是否确有旧数据、旧写入者或不可逆发布影响；兼容策略是否针对这些事实，避免对未上线能力发明旧数据迁移。
- 共享 ID/金额/版本等类型是否来自真实生产者；保存、预览、运行时是否使用同一结构解释。
- 状态/权限/额度限制是否在实际写入边界强制，并覆盖重试、恢复等其他入口；不能只写 Prompt 或禁用按钮。

### 4. 全栈与 UI

- 后台、运营、审核、批量操作是否已有 `ui-flow.md` 或等价说明。
- ViewModel、操作矩阵、权限入口、错误态是否和 API/状态一致。
- 页面主路径是否能在 smoke 步骤中走通。

### 5. 可交付性

- 是否引用当前业务决策；有未确认项时是否按影响指定处理点。
- `tasks.md` 是否能从方案直接拆出，而不是实现时临时发明。
- 功能批次、最小自测和正式审查边界是否明确；关键基础是否独立为依赖前验收批次。
- 最早真实路径是否小且明确，能从真实输入追到最终消费者；是否避免整套前端/后端全部完成后才首次联调。
- 验证是否观察实际行为；是否把结构断言、mock 或 seeded success 误当完整业务成功。

### 6. 当前决策与范围

- 当前业务规则是否只在需求基线定义，其他文档引用且无冲突；历史报告可标为已替代，不要求重写。
- 本轮变更是需求变化、澄清歧义、事实纠正还是实现缺陷；是否把审查建议混成新需求。
- 主线程对疑点的事实前提、当前影响和替代方案是否作出判断，不能把 P0/P1 标签当自动修改指令。

## 角色视角

- 业务架构师：业务闭环和非目标是否清楚。
- 技术架构师：模块边界、扩展点、技术债是否可接受。
- 交付负责人：任务粒度、依赖链、阻塞项是否可执行。
- 资深 Reviewer：正确性风险、遗漏分支、发布/数据风险。

## 输出与收口

正式设计审查只报告：

- **结论**：Ready / Not Ready，以及适用批次或范围。
- **需处理的问题**：证据/前提、影响哪个成功场景、建议与替代代价、阻塞到哪个依赖点。
- **待验证疑点**：最小验证方式；尚未证实不按既定缺陷开修。
- **主线程裁决**：采纳、拒绝、后续处理或需求待确认，并写理由。
- **继续条件**：首批实现需要满足什么，后续批次哪些局部细节可延后。

`Ready` 表示当前设计足以开始约定范围的实现，不表示所有运行时行为已验证。设计级交付阻塞问题必须关闭；可隔离的局部问题记录最晚处理点。主线程汇总独立 scoped CR，不机械投票，不按假想生产前提制造开发期兼容任务。

没有相关变化就复用已有设计结论；修正文档引用或个别措辞可定向确认，不重开整份设计审查。复杂度与审查深度按 `references/stages/plan.md`；代码审查细则由 `references/stages/review.md` 维护。
