# AI 研发工作流入口

这是按需读取规则的入口，完整阶段路由只维护在仓库 `AGENTS.md`。

## 定位规则仓库

方案启动先取得或复用本入口及目标项目自己的 `README.md`、`AGENTS.md`、`CLAUDE.md` 中实际存在的约定正文，再据约定确定任务范围、规则根及阶段方法。入口与项目正文可以分次取得，也可按明确先后有序合批；项目约定仍先于所选根的方法。本入口路径用于定位，阶段和模板属于方法准备。之前可做路径、文件名称发现，已有本轮同版完整正文直接复用。具体API、类型或存储定义由相应阶段的方法选择。用户明确指定的规则目录优先；否则采用项目约定指定根；没有指定时，解析当前SKILL.md真实路径，向上查找同时包含 `AGENTS.md` 与 `skills/` 的入口根。直接软链接和 `platforms/.build/` 安装均沿此步骤。

方案请求先取得项目约定的实际正文，再按其中指定的根取得阶段与方法。可使用下面的只读准备动作，入口根由上述SKILL路径定位；也可用已有文件工具等价取得同一组正文，不以调用哪个脚本作为完成条件：

```sh
python3 <入口根>/scripts/read-plan-context.py project --project <目标项目目录>
```

工具实际返回存在的约定正文，未提供的文件明确说明；项目约定先于所选根的方法，方法完整返回后才细读定义。读取器附带的目录名称只用于定位，名称发现可合批或复用，不是方法前的额外清单门禁。Windows可用已有 `py -3`，不为准备安装运行时。本轮同版完整返回可复用；文件名、哈希或猜测原生注入不等于取得正文。不另写读取回执。

确认选定根中的 `AGENTS.md` 可读后，本次阶段路由及其相对规则、技能、模板路径均从该根解析，不混入另一个安装版本。指定根缺失时说明具体缺口，不能悄悄改读全局旧规则。候选根只影响本次使用，不修改全局链接或安装状态。

## 使用步骤

1. 识别用户要讨论、设计、实现、审查还是发布；用一句中文说明当前阶段。
2. 按选定规则根的 AGENTS 路由只加载当前需要的规则。新写、整体重构、局部评审及轻量方案的工作方式由相应阶段管理，不因出现旧稿就一直停留在局部评审。
3. 项目事实和用户已确认约束优先。已有授权和清楚输入时直接完成工作，不为了换节点反复确认、安装或初始化。
4. 流程、下一动作与中文交接见 `references/delivery/agent-delivery-flow.md`；只加载当前阶段及命中风险的参考，不重复读取完整规则包。时间/token 控制沿用已有计划和记录，按 `references/delivery/execution-evidence.md` 调整方法。

## 阶段边界

- “写方案 / 先讨论 / 先别写代码”：停在需求或方案。
- “按这个落地 / 开始实现 / 执行”：进入已授权实现；按中央节点规则交接与自主处理缺口，局部隔离不自动全局停工。
- 普通任务按范围自测；正式审查按功能批次或基础依赖边界执行，细则读实现/Review规则，不在入口复制门禁。
- 单纯命令输出、事实问答、闲聊、普通翻译不触发完整研发流程。
- 只问本地服务或部署参数，不自动升级为发布或排障。

面向用户的设计、提示词、说明和示例使用中文；字段、命令、路径等稳定机器标识保留原值。
