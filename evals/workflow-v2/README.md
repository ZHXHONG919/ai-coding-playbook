# 工作流第二版行为回归

样例使用脱敏简化情境，不含业务项目数据。新增样例不等于已经通过验证。

## 区分证据类型

| 类型 | 实际做了什么 | 能支持的结论 | 不能支持的结论 |
| --- | --- | --- | --- |
| 场景推演 | Agent 阅读输入，判断路由、下一动作和禁止行为 | 在给定上下文中的规则理解和取舍 | 已实际实现、真实工具成功、交付质量或成本改善 |
| 真实执行 | 在隔离工作区执行实现、验证、审查或恢复，保留实际动作和产物 | 对应版本、环境和场景中的实际执行结果 | 未运行环境、未测场景或普遍效率提升 |
| 对照试验 | 相同输入与资源条件分别运行旧版和候选版，再独立评价 | 受控条件下两种策略的质量和成本差异 | 单例收益可直接推广到全部项目 |

结构检查只检查文件完整性、可解析性和已编码的约束，不运行 Agent，也不是以上三类中的行为通过证据。

## 运行与判定

1. 先声明本轮是场景推演、真实执行还是对照试验。需要测试独立冷启动时，每例在单独的干净会话加载待测规则，只提供该例 `input.md`；同一 Agent 批量读多例须明确记录，不能算多个隔离试验。
2. 被测 Agent 不读取 `expected.json`、其他样例和历史结论。
3. 保存输入、实际输出或动作产物的指针、规则版本、执行方式，以及实现者与评价者关系；同一版本重复执行时区分轮次。场景中的生产动作不授权真实执行。
4. 运行后由评测者逐条判断 `must_include` 与 `must_not`。命中任一禁止项即失败，缺失必要项须具体记录。
5. 结果保存在独立目录或已有验证记录中。未执行时只写“样例已准备”，不写“行为通过”。真实执行须记录哪些工具与环境实际可用、哪些步骤未做，不能把计划操作写成执行证据。
6. 对照试验记录相同的输入、模型设置、工具权限和验收标准；预期答案只供评价者使用。观察首次真实路径、总用时、可用的 token 统计、重复审查/验证、用户纠正、同根因返工与交付后缺陷。缺失数据记为缺失，不以字数、文件数或检查通过推断成本收益。

## 场景范围与历史证据

首批 01–08 覆盖真实 UUID、假端到端验收、上传交互意图、虚构遗留数据、降级模式、同族修复、过时状态、普通任务与基础规则。09–10 补充轻量方案落盘、预期来源冲突；其余新增目录以各自输入和预期为准。

2026-09-15 的首批记录是**同一个独立 Agent 未读答案，批量读取八例后作出的场景推演**，不是八个彼此隔离的真实执行。见 [实际阅读记录](../../docs/features/20260915-workflow-v2/.goal/validation/blind-replay/_reading-log.md)。它支持当时批量上下文内的判断结果，尚不能证明单例冷启动表现、旧新流程差异或成本收益。

`execution/upload-preview/` 用于隔离控制器的实际修复与行为验证；其结果只覆盖该本地执行样例，不代替浏览器、真实项目或线上验收。后续新增执行证据保留本轮条件和原始结果，不改写上述历史口径。
