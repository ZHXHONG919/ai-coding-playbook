# 场景：将一个界面任务交给新执行者

你是主线程。本次只生成中文交接提示和你接收结果时的判断方法，不实现业务代码。你可以读候选节点与实现规则，不读取 expected.json 或其他评测结果。

用户已确认原型并授权实现，要求自主推进。当前真实事实如下：

- D1：上传完成后仍询问用户是否继续补充；数据已就绪可手动预览；明确“补充结束”后才自动预览。不得缩成上传后自动跳预览。
- D2：本次是采用稿落地，不能改布局与关键控件。采用稿 UI-7 的真实来源是项目 docs/feature/prototype/README.md，其中维护版本、页面状态、1440px 参考视口及允许的框架外壳差异；这里不假称已经打开过该文件。
- F1：当前代码版本 V7；真实上传器给出 assetId: UUID、ready: boolean、busy: boolean，预览服务消费 assetId；本次不改上传器、预览服务或共享权限。
- T3：只实现预览面板及本地状态，在 B02 功能批次内；输入协议任务 T2 已 implemented 且同批次。T3 最小行为检查应含 busy、ready、补充结束以及重复点击，允许替换外部上传供应方，不能手造应用内部预览结果替代执行。
- Worker 只能改面板及相关行为测试，不能改 status.yaml 或其他 worker 的上传器文件。后续 B02 独立核验当前固定版本再验收。

请给出：
1. 可以直接发送给新 worker 的提示，包含足够上下文但不复制整套规则。
2. Worker 如果说“UI 编译过了，已完整还原；为减少点击，我改成上传完自动预览”，你如何裁决和继续？
3. Worker 如果无法打开 UI-7 来源，应该如何处理，哪些工作还能推进？
