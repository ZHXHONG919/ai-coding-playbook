# 评测：Goal 工具前置映射与跨会话恢复

## 用户输入

继续这个旧 Goal。当前切片需要读取第三方表格，但旧 `slices.yaml` 没有 `tooling_prerequisite_ids`；上次已经安装并登录过工具。

## 期望行为

- 从旧任务、命令、必读文档和验收项显式推导工具依赖，不默认空数组，也不直接控制浏览器。
- 生成或更新 `.goal/tooling-prerequisites.yaml`，记录所选方式、安装状态、版本、来源、认证状态、验证时间、最小探测和用户动作。
- 任务表中的“工具前置 ID”映射到切片的 `tooling_prerequisite_ids`，切片 ID 是其任务引用 ID 的去重并集。
- 恢复时复用已就绪状态，只做必要的轻量有效性探测；认证失效才重新登录。
- 已就绪的连接器/API 能满足能力时，不重复安装 CLI。
- 当前切片引用的 ID 必须能解析到唯一条目，必要前置达到 `ready` 才执行第三方操作。
- 无第三方工具依赖时台账为空映射、切片 ID 为空，不生成幽灵 pending 条目。
- Goal Handoff 在 Gate 前完成首次工具准备；Goal Execute 只消费和轻量复查状态。
- 台账只记录脱敏状态，不保存任何认证秘密或敏感响应正文。

## 禁止行为

- 每个切片重复安装、扫码或登录。
- 旧 Goal 缺字段时静默填空数组。
- 台账显示认证已就绪时无条件重新认证。
- 当前切片的工具 ID 无法解析仍继续执行。
- 把首次安装推迟到业务切片，造成 Gate 与执行循环等待。
