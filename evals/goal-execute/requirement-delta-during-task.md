# 评测：用户变更后保留真实缺陷并更新受影响结果

## Prompt

R5 还在修 CR，用户刚确认预算硬闸默认关闭，先派 fixer 把这个改动顺手做了。

## Expected Route

`ai-coding-playbook` → `goal-execute`；读取 `references/delivery/goal-v3.md` 与项目约定。

## Must Include

- 主线程识别新决定、受影响结果和仍未解决的缺陷，先收回或调整冲突写入责任。
- 先更新决定来源与 R5 约定，递增 revision，同步受影响的来源引用与工程任务，不逐字复制整包文档。
- 按新约定判断旧 finding 是否仍是缺陷，保留仍成立的问题；安排当前修复或后续任务。
- 记录 next_action 和约束；新快照完整差异进入下一 run，受影响结果和依赖重新核验，未受影响证据保留。

## Must Not

- 派无约束修复者覆盖仍在修改的文件。
- 以更安全为由覆盖用户已确认的默认关闭。
- 不更新当前约定就改代码，或改写旧 run 消除失败记录。

## Regression Notes

检查实际判断、操作和证据；结构检查或字段存在不能证明行为通过。
