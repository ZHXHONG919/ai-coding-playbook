# 评测：验证失败先按原因分流

## Prompt

同一解析问题修了两次，准备再跑一次全量测试后才交给核验者；当前用户结果已经可运行。

## Expected Route

`ai-coding-playbook` → `goal-execute`；读取 `references/delivery/goal-v3.md` 与项目约定。

## Must Include

- 分析失败是否同族和实际影响范围，不机械追加全量测试。
- 独立核验者依据结果预期形成判错样本，固定版本运行验证，再读实现说明和完整差异做 CR；可以在一次 run 中记录两种结论。
- 失败不假称通过；按根因修复并定向复验，必要时由主线程重划范围。

## Must Not

- 无限完整验证后才允许首次独立核验。
- 达到轮数预算就忽略仍有的真实缺陷。

## Regression Notes

检查实际判断、操作和证据；结构检查或字段存在不能证明行为通过。
