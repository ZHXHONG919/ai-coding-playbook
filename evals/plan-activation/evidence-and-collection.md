# 从项目证据形成存储与查询契约

## Prompt

沿用普通“做方案，先不实现”“整体重构已有方案”和“给设备补一个来源类型字段，做简短方案”请求；不提示模板路径、待查缺陷或评分要求。

## Expected Route

完整路径按证据优先、编写规范和模板生成；轻量路径按证据优先和轻量阶段/模板生成，不扩大为全仓核查或复杂方案。

## Must Include

从本次设计判断找到所需定义，已取得的事实直接进入设计；未读与项目未提供不混同，真实缺口只影响相应选择。表名来自实际存储定义，不从接口名猜测；确实缺少映射时可以提出带明确前提的工程建议，其他已确定契约继续给出。

集合区分数据项、外层及具体查询行为，引用可恢复实际覆盖的部分。查询范围、顺序、首查、必要续取与结束都能由契约执行，排序有事实来源；代表路径从请求开始，经查询、选择至后续动作。相同完整查询允许一次定义并引用，不强制重复。

输入与返回都形成可调用的定义：字段位置、类型、取值边界、缺省及省略/null、校验错误可恢复。实际共用输入可定义一次后由各接口明确采用，不能只用相同参数名代替继承的说明；正常和边界请求都依据同一输入契约判定。

## Must Not

不以不可运行或节选标签抹去已给定义；不在相关证据尚可查时将选择整体延期。不从相同集合外层推定排序、筛选、权限范围或游标也相同；不借用另一类对象才有的字段排序。不为修复而强制每个查询分页、全字段台账、全仓扫表或重复相同协议。

## Regression Notes

原轻量枚举与整体重构输入保留不变。增加真实表名不易猜、确无存储映射、完整查询可共用及只读文本四类对照，先冻结判据，再由新上下文作者生成未经补写首稿；实际读取、采用及语义分别检查。继续回归枚举、拒绝原因和有效借用归还，不把旧审核副本补写计入成功。
