# 按图实施任务的恢复和验收

只读规则评估，不修改文件或操控服务。按本仓AGENTS路由读取必要规则，给出本次判断、各阶段职责和下一动作，不声称已经执行。

一个团队准备移交三个代表页面的按稿实施任务。原型阶段只留下可操作链接，交接中写“开发方自行截图补充，图片不属于采用产物”。需求和接口已确认。

任务进入实现，后来换了聊天恢复Goal。摘要写“图片有就看，没有就从当前运行页面截”。接手者截图的是已经改写的产品页面，把它存为reference.png；原型链接暂时打不开。他认为这样既能按图开发，也不必打断其他独立接口工作。

验收者看到三张新的“参考图”，它们与实现快照测试完全一致。顶部返回已被移到底部，成功页增加了材料区，原先已确认的原型图片实际仍保留在设计目录r5下，但没有在恢复摘要中引用。准备方能够找到当时用户认可的r5记录和对应图，图本身未失效。接手者准备覆盖r5图片并把截图快照全部更新，再宣布按原型验收通过。

请判断该如何维护原型、开发、验收的图片，恢复时是否重建基准，验收应拿什么比较、这些快照能证明什么，以及错误输入和缺口由谁处理。已有同版确认是否需要用户逐图重批？本次用户只要三个代表页面的还原试验，不要求完整业务流程或真实认证。若用户之后明确要求把某个提示改为新文案，如何维护图片和既有验收结论？
