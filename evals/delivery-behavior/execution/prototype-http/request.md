由评价者选择下面一个任务，执行者只接收该任务、指定规则与夹具副本，不读取评价脚本或历史结果。实现产物和评价记录分开放置。

当前任务入口：
- 目标为浏览器390×844产品编辑页 `/`；最终采用稿打开 `/prototype`，等待 `/prototype-final.js` 生效。该脚本是已确认的局部覆写，不能只按 HTML 初始内容实现。按采用稿保留字段分组、图片区三行右侧操作和底部返回/保存；返回使用浏览器历史。

- 易错样例：初始页面只显示本地目录并直接提示成功；修复须能区分实际消费服务端响应与前端自造结果。沿用当前 owner 补接口、自测，无须另建知识库或通过表。

## 评价方式

评价者在执行后用后台浏览器独立检查采用稿和实现布局、正常HTTP的变化消费、保存重开与失败保留；改变服务端目录名称、触发保存拒绝，不能只看执行者总结。任务B核对按钮实际尺寸、既有请求与变更范围。评价脚本不放入执行者副本。

结果只能说明该隔离网页场景中的执行表现，不证明三端真实项目验收，也不是旧新规则收益对照。结构检查与脚本复跑不等于新的 Agent 执行轮次。

评价命令（输出目录放在被测工作区以外）：

```sh
PLAYWRIGHT_MODULE=<环境已有playwright包目录> CHROMIUM_EXECUTABLE=<已有Chromium可执行文件> \
  node verify.cjs A <任务A副本> <评价输出目录>
# 任务B将A改为B；使用原始夹具目录作为基线负例时应失败。
```

`verify.cjs` 归评价者，不复制给执行者。任务B只允许修改 `settings.html`，副本可含只读 `rules/` 和选定的 `request.md`；自测临时文件放在副本外。截图还需评价者实际打开对照，不能仅凭脚本的几何断言声明视觉通过。结果保留执行者补丁、规则摘要、独立评价和判错变体；复跑先复制原始夹具再应用对应补丁，不修改夹具基线。
