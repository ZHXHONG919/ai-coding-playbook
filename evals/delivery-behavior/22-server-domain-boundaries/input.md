# 场景输入

预约系统要增加两条已确认的用户路径：申请人提交或撤回预约，管理员确认或拒绝预约。两套页面原型已确认，用户已授权落地。项目是单体应用：ReservationService 已负责预约状态和资源占用，PermissionService 已负责身份及权限；页面通过现有控制器调用它们。

本次确认的新规则是：同一预约的重复确认不得重复占用资源；撤回与确认同时发生时，只允许一个合法状态迁移成功，失败方收到当前状态。两套页面都依赖这条规则。没有跨系统部署、通用流程平台或其他业务复用需求。接口草案尚未说明冲突响应；前端还未开始实现。

请给出简要任务顺序与职责分配，说明两条用户路径如何交付、后端代码放在哪里、这条新规则何时核验。团队同时提出了“每套页面各建一个服务，分别写状态判断”和“先抽出通用审批引擎再做页面”两项建议，请根据现有事实判断是否采用。
