# 评测：按用户结果拆 Goal，保留前端模拟到真实集成的依赖

## Prompt

后台功能的 UI Flow、原型和领域技术方案已确认，请拆 tasks 并生成 Goal。用户要完成内容池选择、发布、审核三条路径，每条都有页面和新 API；希望先看到交互可用，再逐步接真实服务。契约仍需补齐字段、状态和错误响应，各路径包含加载、空态、校验、权限、提交中和失败重试。发布与审核共用已确认的新状态规则，暂无高影响技术未知。三条路径不要求同时开始或同时完成，用户已授权后续连续实现。

## Expected Route

- `ai-coding-playbook` → 任务拆解 / Goal Handoff。
- 读取 `references/plan/task-breakdown.md`、`references/stages/goal-handoff.md`。

## Must Include

- 先列全三条完整用户结果及共享基础，每条路径一个 owner；正式验收挂在结果上。
- 先依据确认原型和领域技术设计定 API；工程任务按当前需要滚动展开，保留 `CONTRACT → FE_MOCK_LOOP → SERVER_CAPABILITY → MOCK_REPLACEMENT → INTEGRATION / QA` 的实际依赖。
- 以一个完整页面或连续功能组为前端执行单元，先由服务端提供开发态 Mock API，FE_MOCK_LOOP 通过真实 HTTP 请求覆盖约定全部交互、状态、ViewModel 和原型对照；普通自测通过后推进，不新增逐任务 CR 或重复用户确认。
- 对应功能组前端完整且自测通过后，分步实现真实服务端、逐项替换模拟并真实集成；已完成前端的组可进入后端及集成，同时其他组继续前端。
- 交付按用户路径组织，后端按现有领域职责和共享规则组织，保留发布与审核的共同依赖；新共享状态语义在依赖扩散前定向独立核验。
- 区分后端设计先行与正式实现后置；若后续出现高影响技术未知，只提前做有范围的能力探针并回写契约，不把整组后端提前包装成探针。
- 模拟用途、责任、退出条件可追踪；任务只引用结果，不另外维护一套 lane 状态或重复产品预期。

## Must Not

- 在所有页面模拟完成前禁止任何真实集成，或等全功能写完才第一次联调。
- 对当前无高影响未知的组，只做首屏或最小成功态就转去常规后端实现，留下已约定前端交互和异常状态稍后再补。
- 后端职责与 API 契约随正式实现一起推迟，或机械地按页面各建一份共享业务规则。
- 用功能点分组掩盖共享契约、前后依赖或缺失的真实结果。
- 把页面 mock 通过当成最终用户结果通过，或让正式业务失败回退到模拟成功。
- Goal Handoff 无依据推翻已确认的交互或任务依赖。

## Regression Notes

检查完整功能组的前端范围、组间推进顺序、后端规则归属和真实替换责任，不能用 lane 标签存在代替判断。这里只准备场景与判据，不代表行为已通过。
