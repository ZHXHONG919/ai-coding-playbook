# Eval: 回答问题时先讲人话再引入术语

## Prompt

```text
这个方案为什么不直接做成异步任务？需要加 Job 吗？
```

## Expected Route

- 可以触发 `ai-coding-playbook` 的通用工程上下文。
- 不需要进入完整方案阶段，除非当前对话已经在复杂方案设计中。
- 按 `AGENTS.md` 的“输出风格”先给自然语言结论，再解释必要术语。

## Must Include

- 先给直接结论，例如“如果处理时间短、失败可重试成本低，就不必急着加 Job”。
- 用用户能理解的语言说明判断依据：耗时、失败重试、用户等待、数据一致性、排队和观测成本。
- 如果使用 `Job`、异步任务、队列、状态机等术语，必须先解释它在当前问题里代表什么。
- 只在确有必要时引入英文名、缩写、模式名或方法论。

## Must Not

- 一开头就堆“异步编排、链路治理、状态闭环、领域抽象、可观测性抓手”等抽象词。
- 用术语替代解释，让用户看完仍不知道为什么要做或不做。
- 把一个简单取舍扩写成长篇背景综述。
- 在没有项目事实时，把推断写成确定事实。

## Regression Notes

如果该 case 仍然出现术语堆叠，优先检查：

- `AGENTS.md` 的“输出风格”是否被入口 skill 读到。
- `agents/AGENTS.template.md`、`agents/CLAUDE.template.md`、`agents/cursor-rules.template.mdc` 是否同步了 plain language 约束。
- 是否需要把高频黑话补进禁止示例，或增加更多真实问答样例。
