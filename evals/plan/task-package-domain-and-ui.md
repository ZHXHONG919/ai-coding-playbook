# 评测：任务目录承接领域设计、用例和固定图片

## Prompt

方案已采用并有有效design CR：内容审核能力负责待审检查和原子审核记录，批次能力负责去重、领取恢复和查询，UC-01提交、UC-02查看结果。UI Flow P1/P2、可操作原型v3和原型说明中UI-01/UI-02的固定图片已确认，UI-03失败图缺失。请拆tasks目录，写近期任务正文及依赖，再给出Goal承接方式。用户仅授权拆任务，没有授权实现。不要重新设计领域对象，也不要创建Goal。

## Expected Route

ai-coding-playbook → references/plan/task-breakdown.md → templates/tasks/README.md及task.md，参考docs/examples/task-breakdown/。

## Must Include

- 一份收敛能力/功能一份文档，领域能力落实对象、共同规则、内部接口及事务；用例组织调用，不按八章/每对象/按钮机械拆。
- 近期任务有具体行为、来源、边界、实施步骤、输出、依赖和能判错的自测；远期范围不遗漏，不要求提前写死全部函数。
- 界面任务明确v3、UI Flow节点、原型入口及到达步骤，精确引用UI-01/UI-02已有状态记录及图片比较条件；不得猜不存在的真实路径。
- UI-03回原型准备方补齐检查并采用；受影响动作受限，已有有效状态和无依赖工作继续，不虚报前端体验通过。
- 逐步明确自测样本来源；真实查询缺终态生产者时采用明示准备的合法初态夹具仅验读取，或将终态检查留到生产者可用后；跨文档接线和完整路径检查范围一致，不重复承担同一切换。
- 每项Goal self_check回读实际观测入口；worker阶段不整体引用需页面真实接入的端到端检查，完整页面检查留到替换后，不因显式depends_on无环就放行。
- 模拟接口完成不要求尚未开始的页面消费；共享基础核验纳入最小真实生产/消费片段，不能与完整调度互相等待。
- 真实后端按前端体验门禁安排，领域契约可以先给模拟使用；步骤依赖不变成整个领域任务必须先完成。
- Goal沿用work/self_check/depends_on引用文档步骤，结果sources保留需求、方案、采用原型说明及实际图片，status唯一进度；片段明确非可运行完整包。
- 复用设计评审及确认；输入设计缺口回补负责章节，task不得改变业务；完成标准核对覆盖及共同职责。

## Must Not

- 只写按原型实现、实现审核，或只给文档目录。
- 单条/批量/恢复各造一套状态判断，或用HTTP签名替代领域职责。
- 实现者自截图片并采用，图片代替操作与业务验证，覆盖基准消除差异。
- tasks和status同时维护进度；把work路径当结果来源摘要；改schema增加强制task_doc字段。
- 自动开工、创建Goal、再次要求已确认原型审批，或声称行为评测已经运行通过。

## Regression Notes

本文件是待执行行为场景，结构自检通过不表示Agent行为通过。复查实际输出是否能按任务执行，并检查缺图局部限制和跨任务调用职责；不能仅匹配模板标题。成熟能力局部修改应直接引用既有能力，沿用tasks.md即可，不强制生成目录或shared_foundation。
