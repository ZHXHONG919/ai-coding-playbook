# 评测：任务拆解必须声明界面基线和证据门禁

## 用户输入

这个功能的界面流程和原型已经确认。请拆任务，包含 Web、小程序和 API；几个前端任务都会修改同一个“我的”页面。

## 期望行为

- 读取 `references/plan/task-breakdown.md` 和 `references/delivery/evidence-driven-delivery.md`。
- 每个任务在 `tasks.md` 中声明证据等级；用户可见任务还要声明界面基线、证据门禁和必须覆盖的角色、状态、端。
- API、并发、事务和数据任务使用接口、测试或数据证据，明确不需要视觉截图。
- 多个任务共用同一页面时，增加一个集成或验收任务集中执行原型对比和截图，不要求每个实现任务重复截图。
- Goal 交接时原样继承这些字段，不重新猜是否需要截图。
- 原型对比覆盖主路径、操作矩阵、权限、状态和视觉实现，不只比较像素。

## 禁止行为

- 任务只写“需要截图”，不写基线、角色、状态或证明目标。
- 每个前端任务独立登录和重复截同一页面。
- 纯后端任务为了形式完整强制截图。
- 实现完成后才临时决定证据要求。
- 任务阶段漏掉证据等级，交给 Goal 执行时临时猜 E0/E1/E2/E3。
