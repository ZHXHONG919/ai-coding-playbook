# T01 批次身份与访问

类型：领域能力；负责人main；结果F1、R1、R2。依据：需求R-01/04/05，方案v12第4/5/6章API-01/02，F1采用记录。无界面变化。

## 1. 目标与职责

批次应用服务唯一负责创建/找回、不可变提交身份、去重与查询归属；HTTP只认证、取可信身份、校验与映射，页面不复制规则。内容合法性归T02，不能在整批接收时拒绝不存在内容。教学已有单条能力沿用现状，不新建通用批次框架。

## 2. 具体行为与协作

| 动作/条件 | 输入与负责工作 | 输出及边界 |
| --- | --- | --- |
| 接受新请求 R-01/04 | 当前content.review，登录态提交人/租户；必填UUID请求标识、APPROVE、1～100不重复UUID；摘要按动作+排序ID | 同事务建ReviewBatch及全部ReviewBatchItem；初态PENDING、attempts=0；202 batchId/resultUrl，不是审核完成 |
| 同标识重放 | UNIQUE(requester_id,request_key)冲突后比较摘要；同序/异序相同集合视同参数 | 原批次202；不同集合409 IDEMPOTENCY_CONFLICT，不自动换标识 |
| 查询 | 当前审核权限、提交人归属；批次ID来自地址 | 同快照读全部项，按contentId升序；RUNNING/PENDING对外PENDING；汇总由条目算，全部终态completedAt=max(processed_at)，不依赖快照已补写 |
| 访问拒绝 | 401未登录、403无审核权限；不存在或他人批次 | 404 BATCH_NOT_FOUND统一隐藏；错误含code/message/traceId，不泄露内部异常 |

批次持有id、requester、request_key、摘要、action、创建/完成时间，提交身份创建后不改。条目逻辑关联batch/content，终态与调度由T02负责；ReviewRecord新增可空batch_id，旧单条保持null。方案第5章图示字段完整采用：无FK/ORM隐式FK/级联，无历史回填，主键(batch_id,content_id)、唯一索引、状态/次数及空值约束齐备。批次不落status列，不加汇总表。内部协作由应用服务调用批次存储完成创建/读取，事务上下文交给审核与结果存储共用；接入真实代码时复用已有签名，若实际缺乏必要事务传播能力先回方案补明，不在HTTP与worker各造判断。

## 4. 缺口与回收

实际业务仓库、启动/迁移命令及连接目标待执行授权后由main核对，阻止真实运行，不影响本教学文档与已定协议。没有业务规则未知；若实际现状相异，回方案处理受影响任务。数据库验证不得建隔离库或清空业务数据。后续独立核验固定版本，记录真实HTTP与存储观测，不能以202代替审核成立。
