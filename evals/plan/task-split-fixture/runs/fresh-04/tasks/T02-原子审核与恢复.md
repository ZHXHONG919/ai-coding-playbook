# T02 原子审核与恢复

类型：共同领域能力；负责人main；结果F2、R1、R2。依据需求R-02/03/05/06/07，A-01/03/04/05，方案v12第4/5/8章及project-context。无界面变化。

## 1. 目标与职责

内容审核能力approveWithAudit是待审核条件更新与审计的唯一负责者；管理端单条、开放API单条和新增批量及恢复共用。草稿提交仅DRAFT→PENDING_REVIEW，导入草稿/正文修改不成为另一审核写入者。批次项保存本次历史结果，不能用当前内容状态覆盖历史成功。

执行模块负责领取、授权上下文传递、有限重试和恢复；批次存储负责在同一事务落项结果，不另判内容状态。已接收任务用提交时保存的可信租户/操作者，worker不重新查询实时权限；查询当前权限仍归T01。

## 2. 模型、流转与协作

条目联合身份(batch_id,content_id)，状态完整集PENDING/RUNNING/SUCCEEDED/BUSINESS_FAILED/SYSTEM_FAILED；后三终态不可再领取。attempts、next_attempt_at、lease_token/lease_until是执行上下文，不属于内容。完整字段与检查约束精确采用方案第5章；成功error_code=null，业务失败CONTENT_NOT_FOUND或CONTENT_STATE_CONFLICT，系统失败PROCESSING_ERROR，终态processed_at必填并清租约。批次汇总由条目算，完成快照异步补写相同max时间。

| 动作 | 能力/事务 | 结果与失败边界 |
| --- | --- | --- |
| 领取 | 短事务FOR UPDATE SKIP LOCKED，候选到时PENDING或过期RUNNING，原子递增次数、更换随机凭证 | 初值每秒扫、并发4、租约30秒；过期且已3次直接SYSTEM_FAILED；这些参数待实测 |
| 执行 | 另开业务事务先锁项，校验RUNNING/当前凭证/数据库时钟租约、剩余至少5秒；事务超时5秒，不含外部调用 | approveWithAudit按租户和PENDING_REVIEW条件更新，审核记录及条目成功共用同一事务；找不到或状态不符写业务失败，其他条继续 |
| 系统故障 | 回滚业务事务后另锁项，仍校验凭证及有效租约 | 未达3次按2秒、5秒回PENDING；第3次SYSTEM_FAILED。失效凭证不改他人结果，数据库不可用不伪造终态 |
| 崩溃恢复 | 过期重领换凭证，崩溃也耗一次尝试 | 旧worker即使恢复也不能提交，终态不重做；不可在整批事务里回滚其他成功项 |

## 4. 未验证范围

租约/轮询/并发为待验证初值，容量在T05；真实环境缺口复用T01。基础独立核验不以假响应或只测repository替代worker—审核—同库事实。页面路径在T04/V03，不能提前要求该检查阻塞S01。
