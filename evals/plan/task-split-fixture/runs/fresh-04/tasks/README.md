## 执行依赖与近期安排

所有编号是稳定引用，不是逐文档串行。P1→P2是一个连续体验组。先用已定协议模拟完整体验，再实现真实能力。约用20%契约与模拟、25%前端体验、30%领域接线、25%集成及修复；真实成本按运行事实调整，质量项不得删。

| 工程顺序 | 输入/依赖 | 输出与继续条件 |
| --- | --- | --- |
| E01：T01/S01 | 已定领域/协议、F1采用 | 服务端Mock及合法场景，局部接口自测；不等页面消费 |
| E02：T03/S01 + T04/S01 | E01的协议与模拟 | 完整P1/P2、真实HTTP消费及五图/隐藏状态体验记录；全部覆盖才放行本组真实后端 |
| E03：T01/S02 | E02体验门禁 | 真实创建/去重/初态查询HTTP与存储，F1独立核验及专项CR；不要求worker或终态生产 |
| E04：T02/S01～S02 | E03及F1有效核验 | 最小真实worker调用审核与存储，F2独立验证与CR；不能等待页面替换才验基础 |
| E05：T03/S02 + T04/S02 | E04及F2有效核验 | 同一步首次共同切换POST/GET至真实服务，首条真实页面路径及R1/R2连续使用过程核验 |
| E06：T05/S01～S03 | E05；F1/F2有效 | 保留、清理、观测、负载验证；最终增量补验，模拟清理 |

E03、E04内部真实接收、worker及查询adapter是本基础生产/消费路径，不被自身基础核验阻止；其他消费者在有效核验后才依赖。E03仅验初态和归属，终态一致性由E04真实生产，再在E05页面整合验证。E05是页面真实切换的唯一负责步骤，不让提交先验证尚未接回的结果页。

## 共同来源与运行说明

仓库根的[需求](../../../../../../docs/examples/plan-output/requirements.md)、[现状](../../../../../../docs/examples/plan-output/project-context.md)、[方案](../../../../../../docs/examples/plan-output/plan.md)为业务、现有能力及协议依据。原型v3入口[HTML](../../../prototype/index.html)，到达步骤、角色与比较条件见[采用记录](../../../adoption.md)的P1/P2和五行UI；各功能精确引用自己图片。开发及恢复先实际打开对应固定图片，图片失效回准备环节，不能自行重截图采用。这里只打开检查过来源图，没有业务运行验证。

虚构项目没有实际应用或数据库；教学现状不是本仓库已有代码。执行前由main定位实际项目的管理端、审核服务、正常启动命令、迁移入口、现有审核读取入口、approveWithAudit及事务传递点，并对照现状输入。核对实际路径/类型/消费者/状态写入者、公共响应、既有批次能力与监控；差异回方案负责位置，不默造目录或签名。必要工具遵循仓库references/delivery/tooling-prerequisites.md；本次交接只用本地文件、Python/Ruby及只读Git。后续应用的CLI、认证、端口未提供，不声称可直接在此启动业务。

main唯一操作管理端、服务端、migration/Entity、共享契约及运行资源（本地API、worker、端口、数据库和配置），未分配者只读。默认当前开发环境，不另建库/容器；执行测试先审查连接目标与建清库行为，仅为样本准备受控新增记录，不清空既有数据。当前不启动服务、不接数据库、不提交推送、不创建App Goal。
