# T03 批量提交体验

类型：用例功能；负责人main；结果R1。来源：需求R-01/04/05、UC-01及API-01、夹具adoption的P1与UI-01/02。与T04构成完整P1→P2功能组。

## 1. 目标与职责

审核人员在本租户列表选择内容，同页确认后提交并进入该批次结果页。页面只组织交互与稳定请求上下文，鉴权、去重、内容审核判断分别交给T01/T02，不将原型内固定数据搬进产品。审核读取使用现有content.review接口，不依赖content.read；原单条审核操作保留。

## 2. 具体行为及协作

| 动作/条件 | 输入、负责者及调用 | 输出和恢复 |
| --- | --- | --- |
| 无选择/选择 | 现有审核读取结果、本租户内容ID | 无选择禁用“批量通过”，选择计数与表格一致；不得以当前状态过滤来替代执行时检查 |
| 批量通过/取消 | 选中集合→同页“确认批量通过”弹框，显示数量 | 打开与取消都不发API-01；取消关闭且保留3项选择，不改成独立页面 |
| 确认提交 | 本次确认生成UUID标识，APPROVE和选中ID；调用POST /api/review-batches | 202只表示接收，根据batchId打开/review/batches/{batchId}，不显示审核成功，不把API resultUrl当浏览器路径 |
| 响应丢失或5xx | 保留本次标识与原参数 | 用原值重试；409提示冲突，不自动换标识；400修正输入、401重登、403不自动重试 |
| 返回后主动重提 | 新用户意图、重新选择 | 新标识，与网络重试区分；超90天旧请求不承诺去重，不能当网络重试 |

精确字段、限制与请求错误结构采用方案第6章API-01，真实创建调用T01，最终逐条处理调用T02，页面不能模拟成功替代。

## 3. 界面与交互依据

采用F1与原型v3，入口[HTML](../../../prototype/index.html)，确认及比较条件见[adoption](../../../adoption.md)冻结范围与固定图片表。管理端审核人员、本租户3条代表内容；1100×780、100%、DPR1、系统中文字体。

| 状态 | 到达步骤/UI Flow | 直接固定图片与还原范围 | 保留项与边界 |
| --- | --- | --- | --- |
| UI-01 / P1选中 | 重置后勾选甲乙丙 | [选中](../../../prototype/images/UI-01-selection.png)，main宽960、内容高度 | 表格、3条计数、批量通过；真实数据可变，布局文案保留 |
| UI-02 / P1确认 | UI-01点击批量通过 | [确认](../../../prototype/images/UI-02-confirm.png)，完整1100×780 | 同页模态、数量、取消/确认提交及背景；下方教学控制区不还原 |

开发/恢复实际打开两图；错图缺图回准备环节，不由实现者重截图采用；实际证据另存不覆盖。其他无选择、加载、空态、400/401/403/409、响应丢失等没有固定图，按业务协议实际操作验证。无授权视觉改版，原型教学控制器不是产品按钮。
