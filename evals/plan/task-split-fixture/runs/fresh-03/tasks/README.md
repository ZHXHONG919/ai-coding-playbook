## 执行依赖与近期安排

P1→P2→返回列表为一个连续功能组，不按按钮拆组。E01协议/工程定位→E02服务端开发态模拟→E03/E04前端消费→E05完整体验门禁→E06/E07真实批次基础及独立核验→E08最小真实审核接线→E11恢复重试→E09基础完整核验→E10联合提交、查询首次切换→E12真实异常与模拟清理；E13保留观测，E14完整业务与性能合批验收。编号是稳定引用而非执行顺序；恢复属于F2同一基础内部，先实现再正式核验，不用局部凭证通过代表整个恢复规则通过。具体步骤、样本和输出在各任务S/V表，Goal表达工程依赖而非文档串行。

E06不能仅因E05 done开工，必须有采用位置、逐动作前后变化和请求证据。缺图/浏览器不可操作会阻止整组体验放行及其后常规真实后端。E06只验接收、身份、初态投影，不能要求尚无worker生产的终态。E08/E09在服务/worker入口实际产生并读取结果，不等待页面；E10同时接回POST/GET，避免提交检查等待后继页面替换。基础核验包含最小真实生产者/消费者，不让核验依赖尚被它阻止的页面。

近期协议与模拟需可定位真实工程；页面只依赖服务端模拟，不等待全后端。远期恢复、清理、监控、容量全部保留，在相应步骤前细化环境配置。粗略成本安排：协议模拟15%、完整体验25%、真实基础与贯通35%、恢复清理量测15%、集成修复余量10%，不是已发生消耗。
