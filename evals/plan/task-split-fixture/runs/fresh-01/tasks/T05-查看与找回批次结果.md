# T05 查看与找回批次结果

> 用例功能；owner：main；结果：R2、R1。依据：[方案v12 UC-02/API-02](../../../../../../docs/examples/plan-output/plan.md)，需求R-05/06、A-06；[adoption P2/UI-03～05](../../../adoption.md)。F1采用与评审状态沿adoption。

## 1. 目标、范围与职责

按地址中的batchId查询、展示进度与终态，失败保留当前结果，支持刷新/历史/保存地址找回和返回列表。真实归属、状态投影及汇总由T01，页面只消费响应。与T04同一连续体验组，不按单按钮拆组跳过门禁。

## 2. 具体行为与协作

| 动作/条件 | 输入与调用 | 可见结果及边界 |
| --- | --- | --- |
| 提交进入/保存地址/刷新或历史返回 | /review/batches/{batchId}读取ID，GET /api/review-batches/{batchId} | 正确批次身份及全部条目，不依赖提交页内存；API地址与管理端地址不同 |
| 有未完成项 | API-02的status、summary、items | 每2秒查询；30秒提示“仍在处理，可稍后查看”，不改业务状态 |
| 全终态 | 消费返回的成功/业务失败/系统错误 | 停止轮询；完成不等全成功；原因按机器码判断，SYSTEM_FAILED显示“处理失败，可重新提交” |
| 网络失败 | 保留已显示批次和条目 | 展示查询失败与“重试查询”；重试GET原batchId；首次无数据失败不得伪造结果 |
| 401/403/404 | 当前身份及归属 | 登录/无权限/不存在或不可访问；不自动重试403，不泄露他人批次；content.review足够，不附加content.read |
| 返回 | “返回内容列表” | 回P1，原型的选择保留表现沿用；返回本身无POST；重新选择再确认才是新意图新key；不提供跨设备历史列表 |

API-02一次返回最多100项、按contentId升序、顶层及条目必返字段、null及统一错误结构精确取方案第6章。summary.total为成功/业务失败/系统失败/待完成之和；内部租约与凭证不展示。结果数据来自服务端，不将原型完成/失败按钮的假业务复制进产品。
