# T03 执行与恢复能力

> 领域能力；owner：main；结果：F1、R1、R2。依据：[方案v12第4章状态机、第5章事务、第8章恢复](../../../../../../docs/examples/plan-output/plan.md)，需求R-02/06、A-04/05；[F1采用](../../../adoption.md#冻结范围)。

## 1. 目标、范围与职责

执行模块唯一负责领取、租约、凭证、重试与恢复；调用T02审核，T01管理批次，不另写可审核判断。条目兼作持久任务，沿单体服务与PostgreSQL边界，不引入队列。

## 2. 具体行为与协作

| 动作/条件 | 工作 | 输出及边界 |
| --- | --- | --- |
| 到期PENDING或过期RUNNING | 短事务FOR UPDATE SKIP LOCKED，attempts<3时原子递增、新随机凭证和30秒租约 | RUNNING；每秒领取、单进程并发初值4可配；终态永不领取 |
| 执行 | 提交身份与当前领取上下文传T02，先锁条目验凭证/状态/剩余租约 | 内容/记录/结果同事务；外部网络不入事务 |
| 系统故障 | 业务回滚后另事务锁项并检查凭证和有效租约 | 第1/2次分别2秒/5秒重试回PENDING并清租约；第3次SYSTEM_FAILED/PROCESSING_ERROR/processed_at |
| 中断恢复 | 锁定过期项，未满3换凭证重领，满3直接系统错误 | 崩溃也消耗一次尝试；旧worker不能改成功或重试状态 |
| 无法保存故障结果 | 数据库不可用或租约过期 | 不宣称状态已改，保留原事实等待恢复；不伪造成功 |

调用输入包含batch/content身份、已接受的租户与操作者、凭证、事务上下文；失败返回区分业务终态与系统重试。终态不能回待执行。全终态后批次快照补max(processed_at)，查询不等补写。内部PENDING/RUNNING均映射外部PENDING；完整枚举、状态条件引用方案第4/5章。

## 3. 界面与交互依据

无直接界面变化，进度由T05消费。须真实锁竞争、故障及读回证据，不能用原型控制器证明恢复。
