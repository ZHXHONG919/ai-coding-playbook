# T04 确认并提交批量审核

> 用例功能；owner：main；结果：R1。依据：[方案v12 UC-01/API-01](../../../../../../docs/examples/plan-output/plan.md)，需求R-01/04/05及A-01/02；[adoption F1/P1/UI-01/02](../../../adoption.md)。

## 1. 目标、范围与职责

审核人员选择本租户内容，同页确认后提交，收到接收响应后进入结果页。HTTP入口从登录态取得身份并鉴权，调用T01；不复制去重或内容可审核判断。列表复用审核读取入口，只有content.review而没有content.read仍可操作。与T05组成P1→P2→返回的完整前端体验组，由main贯穿负责。

## 2. 具体行为与协作

| 动作/条件 | 输入与工作 | 输出及失败边界 |
| --- | --- | --- |
| 选择/打开 | 审核列表返回本租户内容ID/摘要/状态；无选择禁用“批量通过” | 点击仅打开同页“确认批量通过”弹框，显示选中数量，不发API-01 |
| 取消 | “取消”关闭弹框 | 保留3项选择，零提交请求，不改变内容 |
| 确认提交 | 为本次确认生成UUID请求标识，POST /api/review-batches，Idempotency-Key、action=APPROVE、contentIds | 仅“确认提交”才发请求；202按batchId导航/review/batches/{batchId}显示处理中，不能显示已通过 |
| 响应丢失/5xx | 冻结原参数、保留原key重试 | 返回同批次；不能自动换key；resultUrl是API查询地址，不能当管理端页面地址 |
| 输入/鉴权/冲突失败 | API-01统一错误code/message/traceId | 400修正输入，401重新登录，403提示不自动重试，409提示请求冲突不自动换key |
| 主动重新提交 | 返回列表重新选择失败项并确认 | 新用户意图使用新key；原批次结果不改写；超出保留期旧请求不得视网络重试 |

API参数类型、1～100不重复UUID、必填APPROVE及完整错误以方案第6章为准。客户端不得提交操作者。服务端接受时不因内容不存在拒整批，执行才逐项判断。既有单条操作保留，不把已通过项从本测试代表选择中偷偷过滤。
