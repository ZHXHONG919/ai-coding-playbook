# T03 领取、重试与崩溃恢复

采用：夹具 adoption.md 的 F1（需求v1、方案v12、原型v3；教学假定采用且design CR有效）。owner：main。所有步骤只作交接，尚未执行业务。

## 1. 目标、范围与职责

领域能力；关联F1、R1、R2。来源：[方案第4章状态转换、第5章事务竞争、第8章恢复](../../../../../../docs/examples/plan-output/plan.md)、[R-02/06、A-04/05](../../../../../../docs/examples/plan-output/requirements.md)。执行模块负责调度与凭证，内容是否合法只调用T02；批次存储保存结果，执行模块不另建内容规则或消息队列。

## 2. 具体行为与协作

PENDING→RUNNING短事务使用FOR UPDATE SKIP LOCKED，到next_attempt_at且attempts<3，原子递增、随机新凭证、30秒租约。每秒领取，单进程并发可配初值4。长业务事务按T02先锁条目/验凭证及剩余≥5秒，数据库时间判断，5秒事务超时，外部网络调用不进入事务。

| 条件 | 行为及结果 |
| --- | --- |
| 可重试故障 | 业务事务回滚；另开事务锁项，仍须凭证及租约有效；未满3次转PENDING，清租约，2秒/5秒退避 |
| 第三次系统故障 | 同样校验后记SYSTEM_FAILED/PROCESSING_ERROR和完成时间；其他项继续 |
| 过期RUNNING | 锁项；未满3次换凭证再领取，满3次写系统终态；崩溃也消耗一次尝试 |
| 旧执行者恢复、数据库不可用 | 旧凭证不能覆盖新结果或退回PENDING；无法保存则不宣称转换，等依赖恢复后租约重领 |
| 三种终态 | 不再领取、不重跑；全部终态补写max(processed_at)快照，查询不等补写 |

## 3. 界面依据

无直接界面变化。RUNNING和待重试均由API-02呈现PENDING。

## 5. 完成条件与验证

V01（S01）：从API-01真实接收入口准备批次并经正常worker调度；使用可控制时间/故障注入验证2、5秒退避、第三次故障、到期且attempts=3、旧凭证迟到、数据库断开恢复；读回状态/次数/租约/审核记录。worker这一步不要求尚未替换的真实页面；至少两个执行实例验证互斥和租约恢复。本检查随后进入T02/S02独立基础核验。

V02（S02）：页面提交混合项，处理中终止执行进程，在数据库健康且另有实例时60秒内恢复领取，另看最终完成；已完成项无重复审核。连续三次系统故障最终系统错误，其余项完成。60秒是恢复领取，不是完成整批；单实例停机期间不承诺恢复。运行参数均待测初值。
