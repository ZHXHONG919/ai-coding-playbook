# T04 选择、确认、接收与返回的完整体验

类型：用例功能；owner：main；关联R1、R2。采用[adoption F1/P1/P2](../../../adoption.md)、[需求R-01～07及A-01/02](../../../../../../docs/examples/plan-output/requirements.md)、[方案v12第3章UC-01/02、第6章](../../../../../../docs/examples/plan-output/plan.md)。本功能组覆盖P1→P2→返回的连续体验；T05负责结果页细节，但T04/S02统一签收全部体验后才进入本组真实后端。

## 1. 目标、范围与职责

管理端审核人员从既有审核列表选择本租户内容，确认提交，按batchId进入结果地址。仅编排T01的接收能力，真实审核调用T02/T03。列表读取用content.review，不添加content.read。保留既有单条操作。不含批量驳回、取消已提交任务、撤销、跨项目和跨设备历史列表。

## 2. 具体行为与协作

| 动作/条件 | 请求与负责能力 | 页面变化/失败边界 |
| --- | --- | --- |
| 勾选或空选择 | 既有审核读取入口供ID/摘要/状态；勾选不提交 | 已选数量更新，空选择“批量通过”禁用；允许选入后来冲突项，处理时再判断 |
| “批量通过” | 无POST | 同页“确认批量通过”弹框，显示选中数量及提交后说明 |
| “取消” | 无POST | 关闭弹框，仍保留3项选择，不清空不导航 |
| “确认提交” | 为本次意图生成UUID键，POST /api/review-batches，Header Idempotency-Key，Body action=APPROVE/contentIds | 202只代表接收，使用batchId导航/review/batches/{batchId}；不能把API resultUrl当浏览器URL，也不提示审核成功 |
| 响应丢失/5xx重试 | 原键原参数，不新键重发 | 找回同一批次；409显示冲突不自动换键；400修正输入，401登录，403无权限且不自动重试 |
| 从结果返回列表、重新选择失败项 | 用户主动新确认属于新意图、新键 | 返回内容列表；不自动重提、不自动取消旧任务；超过保留期不将旧键当网络重试 |

## 5. 完成条件与验证

V01（S01）：从既有列表进入；无content.read有review身份能选；取消保留选择且网络无POST；确认才发POST，202导航含正确batchId。丢响应后原参数原键，409不换键。用服务端请求记录和浏览器网络检查真实HTTP到达；仅证明模拟消费。

V02（S02）：UI-01→02取消再开→确认→UI-03→UI-04→UI-05→重试→返回；同时覆盖T05/V01未画状态。必须记每个动作后的真实变化、是否触发请求、按钮原文和禁用条件，确认没有“模拟处理完成/模拟查询失败/重置”等产品外按钮。不是本首稿已做过的业务验证。

V03（S03，后期集成）：最早两条内容（待审/状态冲突）经页面确认→真实接收→worker→T02事务→T05结果页，数据库读回1成功1业务失败、仅成功项审核记录；然后A-01三条2成功1失败、A-02重放与冲突。不能只以202/Mock/build证明结果，相关连续路径合批独立验收和CR。
