# T05 找回、查询与理解批次结果

类型：用例功能；owner：main；关联R2、R1。来源：[adoption F1/P2及UI-03/04/05](../../../adoption.md)、[方案第3章UC-02、第6章API-02](../../../../../../docs/examples/plan-output/plan.md)、[R-05/06与A-06](../../../../../../docs/examples/plan-output/requirements.md)。本任务不另做批次历史列表，查询归属/汇总委托T01，展示不重算业务真相。

## 1. 目标、范围与职责

提交人通过接收跳转、保存地址、刷新或浏览器历史打开/review/batches/{batchId}，读取地址ID查询，结果必须保留当前批次对象，不取内存里的最后一次提交替代。只有content.review和本人批次可看。

## 2. 具体行为与协作

| 条件/动作 | 请求与页面行为 |
| --- | --- |
| 进入/刷新/历史恢复 | GET /api/review-batches/{batchId}；展示身份、进度及全部逐条结果，最多100项不分页 |
| 有未完成项 | 每2秒查，同一页面不跨batchId污染；内部RUNNING/等待重试都显示待完成，不提前成功 |
| 超过30秒仍处理中 | 提示“仍在处理，可稍后查看”，仍允许后续查询，不能改成失败或完成 |
| 全部终态 | 停轮询，区分成功/业务失败/系统错误，显示机器码对应可读原因；SYSTEM_FAILED提示“处理失败，可重新提交”；完成不等于全成功 |
| 网络查询失败 | 保留已显示结果与错误提示，“重试查询”才恢复读取，不POST、不清空已有结果，不伪造空批次 |
| 401/403/404 | 重新登录/提示无权限/统一不存在或不可访问；403不自动重试；不泄露他人批次 |
| “返回内容列表” | 返回已有审核列表，不提交；主动重提由T04使用新意图新键 |

完整响应字段、必返/null、错误结构含traceId、summary恒等式及contentId排序精确见方案API-02表，不只根据UI三行硬编码。内容删除仍显示历史ID，终态不随当前内容变化。

## 5. 完成条件与验证

V01（S01）：两个batchId不同返回值，从地址/历史/刷新交替进入确保对象正确；处理中每2秒、30秒提示、混合终态停轮询；模拟返回SYSTEM_FAILED、401/403/404/网络失败，观察保留已有结果、重试GET而非提交POST，返回不提交。配UI-03～05逐状态操作与图片比较，记录汇入T04第6节，不能仅写已操作。

V02（S02）：真实本人/他人/撤权身份及无content.read有review身份分别读回；检查404不泄漏，完成快照未补写仍完成，summary和条目一致、内容删除保留ID。配合T04/V03、T03/V02合批核验；页面正常查询和数据库读回都需要，Mock不证明真实权限。
