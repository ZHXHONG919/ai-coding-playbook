# T06 完成快照与保留清理

领域能力；owner：main；关联F2。采用F1；来源：[需求R-08](../../../../../../docs/examples/plan-output/requirements.md)、[方案第4章计算完成、第5章迁移与清理](../../../../../../docs/examples/plan-output/plan.md)。无界面变化。

## 1. 目标与职责

批次存储/清理服务唯一负责完成快照和安全清理，供去重与查询共同使用。审核记录沿既有审计策略，不随批次删除、不清空历史batch_id。清理后不再承诺请求去重，不新增跨设备历史。

## 2. 具体行为与协作

全部条目终态时完成时间=max(processed_at)，后台补写同值；查询不等补写。每日小批次事务锁候选，只有completed_at已写且早于当前90天、全部条目仍终态才删除；未补快照先补写、留到后续候选，未完成永不清理。先按batch_id删条目再删批次，去重键随批次解除；无FK/级联。锁冲突跳过，可重入；故障只能延长保留，不能扩大删除范围。创建后不追加项，终态不再领取。

## 3. 步骤与依赖

S01：在T02/S02基础当前有效后实现完成快照补写与小批次清理；执行删除前先审查候选条件、SQL与目标库。V01核验F2后才能启用实际定时清理。当前只有教学包，无数据库授权，不运行删除。

## 4. 完成条件与验证

V01：应用创建有代表性的批次并通过正常执行生成结果，再用受控时钟验证刚满/不足90天、超过90天、未完成、终态但缺completed_at、锁冲突及中途故障；清理入口执行并读回候选、条目、批次、审核记录及去重行为。未完成和未到期仍可查；到期删除只移除批次/条目，同键后提交为新批次，历史审核仍保留。失败重跑无扩大删除。不在现有开发库批量删除业务数据，测试连接/建清库行为先核实，仅使用授权代表数据，禁止自行建隔离库。

## 5. 缺口与细化点

实际清理任务入口、现有审计策略及代表数据准备由main在真正接入时查明；依赖不明阻止清理启用，不阻止协议和FE。F2属高影响删除规则，独立核验和CR须覆盖候选锁/删除/去重消费者，不能只用时间判断单测代替真实存储。
