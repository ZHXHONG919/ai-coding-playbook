# 任务拆解首稿：评价者判据

在执行者开始前冻结。执行者不读本文、不读旧答案和修复历史；输入见task-split-fixture/request.md。只评价首次交付，执行者自查允许，交付后反馈补写不算该轮通过。

1. 产物实际写入：目录说明、共同能力/功能文档、完整schema3 goal/status，无业务实现和App Goal。所有任务todo，无虚报业务、独立验收或发布通过。
2. 方案承接完整：需求R01–08、UC01/02、已有单条/开放API共同审核、模型职责与存储、接口协议、事务/去重/授权/恢复/90天保留、观测及非功能目标均有任务/验证位置，不按八章机械拆。
3. 近期任务能执行：实际动作、条件、上下文、输入输出、失败与恢复、具体工程步骤及判错检查明确；不是一句按原型实现，不把已有定义重宣布未知。内部领域能力和HTTP协议分清。
4. 真实依赖无环：服务端Mock完成只需HTTP/夹具，不等待尚未开始的页面；前端消费随夹具变化在前端检查。共享基础具备生产者及最小真实消费协作后独立核验，完整调度/恢复再依赖；不得让核验与消费者互等。
5. 既有实施顺序保留：契约→服务端Mock→本组完整前端→真实模型/能力→逐项替换与真实集成，不用默认态截图或done绕过体验门禁。已有真实能力不重建，不把所有领域能力自动当高风险基础。
6. 图像依据真实可定位：界面任务明确v3、P1/P2与UI状态、同页确认/取消保留、固定图片实际路径和比较条件，主执行者观测到执行者实际打开图片；不虚构采用，不把原型控制区搬进产品，也不复制演示假业务。
7. schema及引用：tasks为ID键映射、必需字段/结果/任务依赖合法且无环，status任务集合一致；work/self_check精确引用任务文档步骤/检查项；产品来源与实际固定图进相关结果sources，不能只在work出现。引用文件实际存在。
8. 唯一状态与恢复：任务不重复维护Goal进度，status next_action一段、点名实际技能、记录与停止条件；无重开已有效确认/评审，无未经授权执行；工程done不当用户结果通过。

结构检验使用现有Goal检查器及本地引用/依赖检查；语义按实际正文逐项判定。任何关键缺失如依赖环、schema不合法、明确业务遗漏、假图片或模糊近期任务均判该轮失败。首稿通过仅证明本夹具与规则版本的一次执行，不推断所有项目效率或普遍稳定性。
