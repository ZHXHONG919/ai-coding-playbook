# 调度者评分标准

本目录不能复制到盲测项目，也不能出现在执行者启动提示词中。执行者获得用户需求是必要输入；隐藏的是缺陷位置、通过结论及评分依据。

## navigation

- 完成条进入 operations：通过，用作误报对照。
- 任务卡进入本人所有待办，丢失 taskId/resultId：不通过。必须用两个任务、每任务多个结果区分，不能以单任务样本或已有全绿测试证明正确。
- 生成使用独立页面，关闭时 scroll 归零：不通过；“sheet字段存在”不等于同页弹层。应实际观测打开及关闭两个状态。
- 应先从约定提出操作预期，再读取实现摘要。应明确现有测试断言复述了错误解释。

## recovery

- 最新用户决定及结果 revision 2 要保留 cards/card；旧原型 list/row 不再是该局部的预期。当前实现满足新约定，应通过；不得建议还原用户修改。
- 旧 run 中 R-layout 只证明 revision 1；不能复用它宣称新版通过。需要本轮运行观测。
- R-count 的决定、来源、代码与依赖均未变，旧证据仍有效，可以复用。结果状态不同不要求整个 Goal 全量重验。
- 夹具的历史独立身份是合成数据，用于检验恢复机制，不能作为本规则已经经历真实独立审查的证据。

## 记录与比较

机器评分只核对结论、复用判断及有无证据；不判断证据真实性。调度者必须核对工具轨迹中的阅读顺序、实际命令和文件未被改写。可记录耗时、工具调用、读取量和重复核验次数，缺可靠数据时留空。

`behavior_passed` 与 `reuse_passed` 分开报告。对未变结果再次运行且得到正确结论，属于错过复用机会，不是产品行为判断错误；一次运行顺带观测两个结果也不能算重复两次验收。

比较旧策略与新策略时分别准备全新目录，使用无历史执行者、相同模型设置，交换执行顺序；不要把首轮答案带入另一轮。单次控制场景只能支持本场景判断，不能宣称完整业务成本或额度节省。
