# 本例界面依据：当前缺口与交接写法

本例没有已确认的界面原型和固定图片。方案中的工程图不能替代界面图片，本文件也不是原型采用记录。以下是需要由原型准备环节填入的交接示意，不是存在的文件或已确认版本。

| 页面/状态 | 采用入口与操作 | 固定图片精确定位 | 比较与约束 |
| --- | --- | --- | --- |
| 管理端列表选择及确认 | 待提供：采用版本、实际入口、UI Flow节点和选择后打开确认的步骤 | 待提供：该版本已保存且实际打开检查的图片路径 | 待提供：视口、内容区域、角色与代表数据；按钮原文、取消及保留上下文 |
| 批次结果处理中 | 待提供：从提交返回进入该批次结果页的步骤 | 待提供：处理中状态固定图片路径 | 方案已确定显示处理中，不得显示审核完成；具体布局由采用图片确定 |
| 混合终态及关键失败 | 待提供：到达对应原型状态的实际操作 | 待提供：混合结果及所选关键失败状态图片路径 | 请求失败保留已显示结果；其他无图状态仍按原型/方案实际操作 |

解除缺口时引用实际采用版本与确认依据，在T03对应行替换上述待提供内容，或精确引用原型说明中包含同等信息的状态记录。稳定路径形态可以是业务项目的prototype/<采用版本>/images/<具体状态>.png，但本例不创建空图片，也不声称这些路径存在。原型准备方先截图、打开检查、随原型采用；实现者消费该版本。参考图和实现截图分开，缺图/错图/版本冲突不能由实现者自截候选图解除。

如果已有其他任务共享的有效原型与图片，直接定位同一记录，不重新截图或逐图审批。正式Goal的结果sources应引用真实采用说明及实际图片；不能只引用本缺口说明便宣称视觉输入已具备。
