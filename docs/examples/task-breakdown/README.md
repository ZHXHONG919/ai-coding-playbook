# 从批量审核方案到任务与Goal

本例承接[技术方案](../plan-output/plan.md)、[需求v1](../plan-output/requirements.md)及[教学项目现状](../plan-output/project-context.md)。均为虚构教学输入；方案仍待设计评审，不能把示例任务视为开工批准或已验证业务。本例不新增单条审核用例，既有单条与开放API只作为共同规则的消费者。

## 为什么这样拆

方案第4章已确定内容审核、批次应用服务、执行模块和存储组件的职责。T01落实共同内容审核与事务接入，T02落实批次身份、结果和恢复能力，T03组织UC-01提交及UC-02查看结果的连续体验。功能文档不是三个孤立实现：批量和恢复都调用内容审核能力，不能复制状态判断。两个用例在同一连续使用过程中，放在同一功能文档，仍分别验证结果。

| 需求/结果 | 负责能力与任务 | 完整功能与验证 |
| --- | --- | --- |
| R-01、R-04：接收、去重和冲突 | [T02](T02-批次处理能力.md) S01/S03 | [T03](T03-批量审核与结果查看.md) V01/V02；结果R-submit |
| R-02、R-03、R-07：独立审核且成功事实一致 | [T01](T01-内容审核能力.md)、T02 S04 | T01 V01/V02与T03 V03；基础F-review及结果R-process |
| R-05：授权时点、查询归属 | T02 S03/S04/S05 | T02 V02、T03 V04；结果R-query |
| R-06：中断恢复、有限重试 | T02 S04 | T02 V03及T03 V03；结果R-process |
| R-08：保留与到期清理 | T02 S06 | T02 V04；结果R-retention |
| 需求非功能目标、方案第7/8章 | T02 S07 | 性能条件、监控和恢复观测；不能用HTTP成功代替 |

这些结果名仅用于本例映射，不表示已创建真实Goal或均须单独验收批次。正式Goal按实际用户结果和高风险共同规则建模，不为每个普通能力新增shared_foundation。

## 步骤依赖与顺序

T01/S01和T02/S01承接已评审契约；T02/S02提供开发态模拟。T03/S01随后通过真实HTTP完成本组全部前端交互，S02按review规则核对采用稿和实际动作覆盖。之后先T02/S03实现真实模型与接收，再T01/S02/S03实现并核验最小原子协作，随后T02/S04扩展完整调度/恢复，T03/S03逐项替换，再完成查询、保留、观测及真实验收。编号不是串行顺序，不设置“T03依赖整个T02完成”。T02/S03先提供真实模型及接收；共享审核基础内部再实现T01/S02包含的真实生产者、最小批次消费adapter及必要凭证保护，于S03核验；T02/S04完整调度及恢复依赖该有效结论，避免核验等消费者、消费者又等核验的循环。模拟准备仅检查可调用HTTP和夹具，页面消费检查放在T03/S01/V02，不能反过来阻止前端开始。有限技术探针需要具体问题及停止条件，本例不以真实保存冒充探针。

## 当前界面依据缺口

已有方案的architecture/domain/ER图片是工程图，不能当作界面参考。本例未提供可操作原型、采用记录及固定界面图片。详见[界面依据](ui-handoff.md)。因此它是可阅读的拆解示例，不是可直接执行前端的完整交接包；本组前端实现及随后真实后端步骤受限。可以继续方案评审、契约准备及不依赖该界面的工作，不得宣称前端体验已通过。

## Goal如何承接

schema 3无需增加字段。例如已有Goal可用下面的工程步骤记录（片段，非可运行Goal包）：

```yaml
tasks:
  T02_S02:
    owner: main
    results: [R-submit, R-query]
    work: "按 docs/tasks/T02-批次处理能力.md 的 S02 提供开发态模拟接口"
    self_check: "执行该文档S02的正常请求与错误夹具检查"
    depends_on: [T02_S01]
  T03_S01:
    owner: main
    results: [R-submit, R-query]
    work: "按 docs/tasks/T03-批量审核与结果查看.md 的 S01 完成本组前端体验；先补齐并采用界面依据"
    self_check: "该文档V01/V02/V04的模拟阶段，以及界面状态实际操作"
    depends_on: [T02_S02]
```

片段假设业务项目将本目录放在docs/tasks，R-submit等结果和T02_S01已定义；照抄片段不会满足Goal结构检查。真实开工包仍需有效评审、界面依据、全部结果、可解析基线和status。将需求、方案、原型说明、实际固定图片放入相关结果的sources，不能只在work写路径；当前负责状态的固定图片文件必须由相应结果source直接引用，检查器按现有整文件摘要处理。任务说明变化需人工判断影响，work不是产品来源摘要的替代。

进入Goal后，各步骤状态只在status维护；T01/T02/T03正文保留具体工作及验证说明，不勾选另一套进度。执行与恢复读取当前步骤及相应来源，并实际打开已采用图片。参考图准备与采用不在本例伪造，运行证据也未生成。
