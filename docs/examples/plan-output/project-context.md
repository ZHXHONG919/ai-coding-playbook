# 批量审核示例：已有系统的教学输入

这些是虚构项目的现状约定，供方案推导使用，不是当前仓库的业务代码事实，也不代表经过运行验证。业务规则仍只在 `requirements.md` 定义。

审核列表及详情以 `content.review` 检查当前人员，返回本租户审核所需的内容ID、摘要和状态。普通内容浏览另用 `content.read`，审核页面不依赖该浏览接口；审核人员不一定拥有浏览权限。

本例相关现有行为包括管理端单条通过、开放API单条通过和草稿提交。前两个入口完成当前审核鉴权后，均在事务中调用内容审核能力的 `approveWithAudit`；该方法按租户和待审核状态条件更新内容，并用同一事务写审核记录。它接收可信入口提供的租户与操作者，不再查询实时权限。草稿提交只允许 `DRAFT → PENDING_REVIEW`；导入仅创建草稿，正文修改不写审核状态。本教学输入中没有其他内容状态写入者。

因此，已有能力对审核状态及记录的保护可以复用。新增批量入口仍需设计提交鉴权、已接受任务的身份传递、执行进程接入和条目结果的原子写入；已有入口存在不证明这些新增协作已实现。实际接入项目时，应以其真实调用者和事务接线替换本教学输入。
