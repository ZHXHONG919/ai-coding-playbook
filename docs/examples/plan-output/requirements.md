# 内容批量审核：示例需求

> 版本：v1 · 教学输入

本文是用于检验方案模板的虚构教学样例。业务规则、容量和时限均为演示设定，不代表真实项目或用户已经确认的需求。

## 背景与目标

审核人员在待审核列表逐条通过内容，重复操作较多。希望一次提交多条内容，并能通过保存的结果地址或浏览器历史返回查看每条结果；本次不做跨设备历史列表。

## 业务规则

| 编号 | 规则 |
| --- | --- |
| R-01 | 具备 `content.review` 权限的人员可以提交批量通过；每批 1～100 条，不允许重复内容 ID。 |
| R-02 | 提交后异步处理，每条独立提交结果，一条失败不影响其他条。 |
| R-03 | 处理时重新检查内容是否待审核；状态不符为业务失败，不再次审核。 |
| R-04 | 请求标识由前端生成；同一提交人、同一标识及相同参数返回原批次，参数不同则拒绝。 |
| R-05 | 批次仅允许提交人查看；提交和查询都检查当前审核权限。已接收任务以提交时授权执行，之后权限变化不撤销任务。 |
| R-06 | 进程中断后允许恢复。单条系统故障最多尝试 3 次，仍失败则记为系统错误；结果必须区分成功、业务失败和系统错误。 |
| R-07 | 内容通过、审核记录和该条成功结果必须同时保存；不得出现内容已通过而结果显示失败。 |
| R-08 | 未完成批次不清理；完成后结果与去重记录至少保留 90 天，之后允许清理。审核记录按已有审计策略保存，清理后不承诺请求去重。 |

## 本次不做

批量驳回、撤销通过、自动判断审核内容、取消已提交任务，以及跨项目审核不在范围内。

## 验收场景

| 编号 | 场景与预期 |
| --- | --- |
| A-01 | 提交三条内容，其中一条已通过：两条成功、一条业务失败，汇总总数为三。 |
| A-02 | 相同请求并发或网络重试：仅生成一个批次；换一组内容沿用标识：返回请求冲突。 |
| A-03 | 两个批次并发处理同一内容：最多一个成功，另一个业务失败；成功动作仅有一条审核记录。 |
| A-04 | 处理中终止执行进程：租约到期后其他执行进程恢复，已完成项不重复执行。 |
| A-05 | 单条系统故障连续出现三次：该项最终为系统错误，其他项仍可完成，批次最终完成。 |
| A-06 | 其他用户查询批次返回不可访问；权限已撤销的提交人也不能查询。 |

## 非功能目标

演示负载为 10 个并发批次、每批 100 条：提交接口 P95 ≤ 300 ms，查询 P95 ≤ 300 ms；健康依赖下单批 95% 在 30 秒内结束；执行进程中断后 60 秒内恢复领取。具体环境和样本量应在真实项目中确认。
