# 原型图片工作流发布说明：2026-10-23

按已确认原型还原界面时，采用“原型阶段准备并确认图片 → 开发阶段按固定图片实现 → 验收阶段按同版图片检查”。详细规则只维护在[证据驱动交付](../../references/delivery/evidence-driven-delivery.md)，阶段和Skill引用同一来源。

## 本次采用

| 阶段 | 职责与边界 |
| --- | --- |
| 原型准备与采用 | 开发前准备关键状态图片，打开保存原图核对，随原型确认采用版本；在现有说明关联图片路径、端/角色/状态和比较条件 |
| 开发与恢复 | 实际打开已采用图片按图实现；换聊天恢复仍消费同一基准，缺图错图回原型准备环节，不自行补截并采用 |
| 验收与修复复核 | 用同版参考图与实际画面对照；既查遗漏，也查未经授权的新增、移动和默认展开。实际截图及实现快照不能成为参考基准 |

图片负责画面，可操作原型负责交互，已确认需求及API/状态约定负责业务、数据与请求。三者不能相互代替。已有同版确认直接复用，不要求逐张额外审批；普通一字或局部样式修改复用有效输入，不强制制作整套图片。用户新决定进入新采用版本，保留旧图，只使受影响证据过期。局部缺口不阻止无依赖工作。

变更涉及入口路由、原型/React/Goal Skill、任务拆解、实现/验收/规则诊断阶段及回归检查。没有新增Skill、全局安装动作或自动拦截工具。规则约束仍需要执行者遵守和验证者实际对照，不能承诺模型今后必然照做。


需要回退时，通过后续PR撤销本次规则及场景检查清单的对应改动，不删除历史证据、不覆盖业务项目已经采用的图片。实际合并状态以PR为准，本说明不把提交成功当作已合并发布。
