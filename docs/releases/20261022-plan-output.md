## 采用内容

普通“做方案”先实际加载项目约定、相应编写方法与模板，再按依赖取得业务定义。新写与重构采用同一推导过程；轻量修改只展开实际改变或依赖的内容。方案评审继续使用同一份规范，不维护另一套章节标准。

八模块沿“需求与事实→用例行为及所需查询→共同职责、属性和关系→存储与API→连续实例、观测及实施验收”展开。领域属性先从合法动作推导结果范围；选定模型或表示后，继续检查受影响的旧契约，明确兼容接续。枚举、状态机、逻辑ID关系、图与API采用同一定义。细则见[完整规范](../../references/plan/plan-writing-guide.md)和[模板](../../templates/feature-design.md)，不在发布说明重复维护。

采用清单包括52项正式文件：14份修改、38份新增。另更新仓库README并增加本文。批量审核[示例](../examples/plan-output/plan.md)、需求、项目事实及图稿都位于正式目录，能随仓库独立使用。原候选的讨论、原始运行日志与历史结果不属于正式运行依赖，没有随本次PR提交。

## 安装与后续复查

合并main后，按[Codex](../codex-usage.md)、[Cursor](../cursor-usage.md)或[Claude](../claude-usage.md)安装说明采用。修改平台overlay后需要重跑正式安装脚本，规则正文与直接链接则从同一仓库根读取。

```bash
bash scripts/check-playbook.sh --repo-only
python3 scripts/test-read-plan-context.py
```

全局安装检查使用 `bash scripts/check-playbook.sh`。普通请求的行为回归按[新写](../../evals/plan-activation/new.md)、[重构](../../evals/plan-activation/refactor.md)、[轻量](../../evals/plan-activation/light.md)及[枚举](../../evals/plan-activation/light-enum.md)准备业务输入，再保留实际加载与未经补写首稿；这些场景说明不自动运行Agent。

安装回退需要保存旧源与三平台原合成目录。原脚本没有自动回滚，尤其不能假定旧源重装就等于恢复曾经较旧的合成文件。合并与本机采用结果以实际PR状态、安装记录和本次交付说明为准。
