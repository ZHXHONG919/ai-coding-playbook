## 已核实事实

- 当前安装通过实时软链接读取原 main 工作区；直接在那里编辑会提前应用。候选位于独立 `codex/workflow-v2` 工作树，基线为 `8b59b6a`。
- 旧规则在入口、实现、Goal、模板与 eval 中重复要求逐片验证/CR及证据确认；需要同步改变，不能只改一处口号。
- 历史问题包括真实上游类型与 mock 不同、最终产物未进入真实请求、自证测试、用户意图在修复中丢失、假想历史数据引发多余兼容、同类规则局部修补和过时状态误导恢复。部分后续要求是需求变化，不能算成初版缺陷。可复用规则和样例已脱敏。

## 设计

统一节点图和中文交接提示在 `references/delivery/agent-delivery-flow.md`；审查时机与裁决在 `references/stages/review.md`；状态与连续执行在 `skills/goal-execute/SKILL.md`。入口只路由到相关规则。

任务状态为 todo / in_progress / implemented / accepted；已有实现但依据失效时用 awaiting_revalidation，保留原记录但不能满足消费者依赖。批次为 pending / in_review / accepted。基础规则以有限范围独立成 foundation 批次，依赖方等待其验收。普通任务在同批次内可依赖 implemented；跨批次等待 accepted。最后的 final 批次核对完整差异与验收，复用仍有效证据。

快照记录代码及相关需求/契约的内容哈希，包含未提交、新增和删除。非最终批次声明 snapshot_scope 的源码范围和相关契约，自动纳入前置批次与任务定义；独立范围变化不重复触发验收。最终快照覆盖全部差异及登记契约。只读检查器验证结构、依赖、证据引用与新鲜度，不证明报告的语义正确性。旧 Goal 或早期候选快照迁移必须核实原报告范围并复验，不静默解除原项目要求。

## 本次采用的流程

1. 以已获用户确认的分析和 D01–D06 为输入。独立设计审查先指出快照有效性、基础范围、检查点与最终完整覆盖四项问题；在批次/状态契约中解决。
2. 基础契约：先定 schema、模板与只读检查器；用真实模板→解析→状态检查→反例失败跑通最小路径。上游文档和验证提示是可独立进行的工作，并行修改，不做逐文件 CR。
3. 功能批次：整合入口、方案/任务、执行/验证/CR和模板，统一矛盾；独立场景回放与隔离执行作为行为证据。
4. 收尾批次：冻结候选版本，独立 CR 与仓库检查，裁决后只复核受影响范围。最后核对原安装源/软链接保持不变。

## 交付边界

候选文件与验证记录供继续讨论；不安装、不推送、不合并原 main，不运行业务仓库服务或真实供应方。真实 Goal 的成本和交付缺陷变化需要用户决定应用后再观察。

## 2026-09-16 定向修订

后续独立审查发现：基础批次审查期间的新增文件漏检；全仓中间快照使无关批次修改导致重复验收；轻量落盘入口仍强制多文档。用户补充原型还原案例并授权继续优化、留存执行证据。因此重新打开受影响批次，历史通过记录仅证明当时范围。

本轮并行修复检查器、原型交接、轻量入口；主线程负责执行证据设计及整合。保留原审查策略，以范围内新增/删除/修改反例验证快照，再进行独立定向审查。证据放在 `.goal/execution-log.md`，引用现有验证和 CR；不复制完整对话或业务数据。

## 2026-09-16 全流程收口

用户进一步明确：开工后自主推进，局部能力缺口可先约定接口协议、隔离逻辑并继续；这应服务于整体效率和按期交付，不能不断添加补丁。将此前分散的例外归并为五节点职责、统一六项交接信息和主线程运行时影响判断。方案负责可执行输入与真实路径，执行负责协议/能力依赖及回收，核验负责独立预期和真实证据，交付沿原成功标准判断。

中央流程维护语义；阶段规则只保留专属动作与状态，模板落实信息。沿现有任务/批次表达协议与真实能力两类依赖，不新增状态机字段；首次 Gate 与恢复时任务就绪分开。两个只读子 Agent 独立指出同样的依赖混淆、交接丢失与自动人工对齐问题，主线程采用对应结构调整。通过新增上下文隔离场景与契约依赖结构探针核实；检查器未变的既有证据按哈希复用，不用文档修改重复跑整套测试。

## 2026-09-17 并行与恢复收口

用户准备将候选流程用于大需求，授权修正讨论中确认的两处执行缺口：恢复入口遗漏 `resume.md`，以及规则允许跨任务并行但检查器只接受一个进行中任务。沿现有 `current_slice` 与 `active_workers` 表达主线程焦点和其余写入责任，保留任务与批次依赖。失联 worker 仍保留写入范围，查实停止并检查产物后才交回。已有全部或部分改动需要暂停恢复时统一用 `awaiting_revalidation`，如实记录实际进展与未验证项；无需伪造完整自测，也不以 stale 绕过依赖。

主线程修改检查器及规则，子 Agent 在独立文件补反例，另一个子 Agent 做定向审查。用原有脚本回归验证状态契约，补恢复场景说明；不新建流程节点，不扩大到尚未提供的业务需求。更复杂的来源冲突、真实项目效率和 UI 还原效果留待实际应用观察，不以本次结构检查代替。
