## 返工归因

- F-SNAPSHOT：旧检查器只枚举快照中已有文件，且中途抓取全仓差异；这是已复现的设计/实现缺陷。首次引入的精确节点未核实，首次在后续独立反例审查发现。优化目标：范围内变化拒绝、独立范围变化不重复验收；测试与定向 CR 证明修复。
- F-ENTRY：上游减轻流程，但 kickoff 与部分调用方仍要求多文件和全量读取；已核实的规则矛盾。按同族修复相邻调用方，不仅修改被指出的一行。
- F-UI：历史案例表明源码审查与后续实际页面存在差异；采用稿没有持续约束实施和验收。无法从可读记录断言当时 worker 没读原型，根因尚不能归结为单一提示遗漏。新增交接约束与首次代表页面校准，后续真实使用需观察效果。
- D-EVIDENCE：本轮用户新增执行证据需求，属于需求变化，不计为上一版实现缺陷。
- F-RESUME / F-VERIFY：本轮独立规则审查发现已授权任务的正常未提交改动仍可能触发文档落盘停工，以及 React 固定 build/test 与按风险验证矛盾。主线程采纳并修正文件编辑边界和验证选择；不放宽切分支/合并等 Git 命令授权。说明独立审查仍有实际价值，减少频率不等于取消审查。
- F-ACCEPTANCE：独立检查器审查补充反例发现模板可预填 passed、待复验仍可能保留无有效证据的 passed。主线程采纳；拒绝简单强制所有 pending 验收项清零的修法，因为共享验收编号会导致上游/下游恢复相互等待。明确同一编号只指完整断言，仅其他当前有效的非最终批次可继续提供证明，整体完成仍要求所有批次通过。
- F-RECORD：合成留证试验初稿 64 行、3853 字符，归因正确但多处复述；明确短任务一个事件表加少量归因后，同一执行者定向修订为 27 行、1674 字符。原稿与修订稿都保留。字符减少只是该产物变短，不是实际 token/耗时收益证明。
