# 05 降级不等于真实模式

我按 ai-coding-playbook 进入验收缺口定位与排障阶段。**当前只观察到接口可达、执行进入 fallback、页面显示固定引导**；未证明知识库参与模型生成，也未证明 fallback 的持久化或后续读取完整成功。

## 下一步与最小验证

1. 先从实际会话入口的调用关系、相关配置与该请求日志定位降级原因。分别核实检索入口是否执行、失败类别及返回、模型调用前的分支判断。原因未知，不能直接认定为外部故障或马上修改业务代码；一次验证一个主要假设，日志检查不暴露凭据。
2. 保留并验证合法降级：经实际会话入口触发检索不可用等已有降级条件，观察真实编排选择 fallback、固定引导符合契约，若验收包含保存，则由应用写入后从同一存储读回。正常未调用模型的 fallback 不应被“缺少模型调用”校验误拒绝。
3. 尽早建立正常路径：已知知识条目经实际检索和上下文装配进入模型请求，检查来源/内容在供应方边界可见，实际模型输出被应用消费并保存，executionMode 与调用证据一致。核对最终结果，不能只看 200 或某个 mode 字段。
4. 本地可先用冻结的检索/模型边界响应验证应用装配与消费，且记录替换边界；不能把它写成真实知识检索、模型效果或真实模式验收已通过。真正的知识库参与模型生成需要检索及模型路径的相应运行证据。

本轮是只读评估，不调用任何外部服务。后续如果真实依赖必须由外部环境提供，先明确可用环境、现有授权和所需能力，再运行最小代表性场景；不可用就记录具体缺口、影响、owner 和恢复动作。

## 继续与完成判断

可以继续本地原因定位、降级回归和不依赖正常模式验收的工作。正常路径是本次明确验收内容，证据不足时批次不能 accepted，不能改成“降级算成功”，也不能移到未来发布再测。

输入未说明检索失败根因、模型配置、调用环境、存储契约和生成验收样例，因此不能承诺排障耗时、正常模式可用或所有 fallback 分支已覆盖。

## 使用的规则与矛盾

使用候选入口、交付流程、测试范围、交付证据、排障、Review、`skills/ai-provider-integration/SKILL.md`。Provider Skill 以真实 smoke 为验证步骤，但具体调用仍受本轮范围约束；这不使未调用部分获得验收。排障规则与证据规则的全量回归措辞差异见 `_reading-log.md`。
