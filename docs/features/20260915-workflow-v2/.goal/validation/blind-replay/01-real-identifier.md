## 动作与最小验证

1. 先沿订单标识生产者、前端上传参数、服务端校验、附件关联写入和读回入口核实类型及传递方式。保留服务端 UUID 校验，不为现有 mock 放宽契约。
2. 正例使用实际创建接口产生的订单 UUID，或项目认可的本地订单 fixture；这个 UUID 必须对应实际订单记录。前端/单测正例改用该类型，`order-1` 保留为非法输入反例，不能只替换成一个格式正确但不存在的随机 UUID。
3. 从实际上传入口上传小型本地文件，经过真实参数校验和关联业务逻辑；从同一存储读回附件，核对关联的是该订单。前端观测发出的 UUID 与上传后订单附件展示/重新读取一致。
4. 通过相同入口发送 `order-1`，断言按现有接口契约拒绝且没有创建附件关联。若实际改动涉及订单存在性检查，再补“格式合法但订单不存在”的反例，响应码依据项目现有契约确定。

外部文件存储可在约定边界替换，不能手工创建最终附件关联记录来证明上传成功。先选已有相关接口/组件测试；不默认全仓 build 或全量回归。
