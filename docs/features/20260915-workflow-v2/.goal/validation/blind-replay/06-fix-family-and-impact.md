# 06 同族问题与影响域

我按 ai-coding-playbook 进入缺陷修复与定向复审阶段。预览按末段匹配违反完整三元坐标契约；生成复制相同解析逻辑，已是有代码线索的直接影响面，不能因没有失败报告而忽略。

## 修复安排

主线程核实完整三元坐标的类型、生产者及所有消费位置，把预览与生成归为同一问题族。先列合法匹配规则和同名冲突反例，再改为使用完整坐标身份查找。能安全复用现有解析器则复用；需要统一两处逻辑时采用最小共享实现，不扩成无关架构重构，也不保留未经需求支持的末段兼容匹配。

按钮颜色作为非阻塞后续建议，记录 UI 负责人、当前无验收影响及下次界面优化处理点，本次不混入修复差异。

## 最小复验与复审

- 构造末段相同、前两段不同且内容明显不同的两个合法坐标。分别选中它们，从实际预览入口和实际生成装配入口检查选择与最终消费内容，不能只测一个底层解析函数。
- 覆盖契约已规定的缺失/不存在坐标行为，确认不会悄悄退回末段误选；保留普通合法坐标可用的检查。具体错误形式以项目契约为准，不新加产品限制。
- 扫描同一解析规则的其他直接消费者、保存/读回或重放入口；只对实际相关路径增加检查。若生成接供应商，在外部边界截获真实请求并固定返回，不需真实付费生成。
- 修复自测后固定版本，独立验证和 Reviewer 可并行；Reviewer 定向检查原缺陷、两个入口、共享解析所有受影响调用方以及上述反例。复用无变化的既有检查，不重跑整套历史 CR。

如果修复后同族问题再次出现，先检查遗漏的生产者/消费者和共同原因，再统一修复；不能继续逐处补丁或因到达轮数就放行。只有影响面无法可靠隔离、共享契约进一步扩大或项目要求时才扩大回归/复审。

## 继续与完成判断

当前身份选择错误影响正确性，应修复并复验后才能验收。无依赖工作可继续，颜色建议不阻塞。两条路径最终版本证据充分、定向复审无当前阻塞后，此问题族可关闭；整个批次还需满足其余验收。

没有提供实际三元坐标格式、源码和消费者清单，不能断言只改两行或只有两个调用方。

## 使用的规则与矛盾

使用候选交付流程、Review、TS Review、测试范围、交付证据、排障规则。全量回归默认条件存在措辞冲突，本例以实际问题族和可隔离影响域决定验证范围，未按“共享契约”词语自动要求全仓回归。
