# 04 不虚构遗留数据

我按 ai-coding-playbook 进入审查裁决阶段。**不接受“必须回填和双读兼容”作为当前阻塞 finding**：前提只是猜测，且与给定的未发布、迁移未应用、测试库无表及仅需新建流程相冲突。

## 裁决与范围

记录为“当前缺陷依据不成立，拒绝扩展实现范围”，附上上述输入事实。没有历史写入者、已发布版本、已应用迁移或实际旧数据的证据，就不实现 backfill、双读或兼容开关。

不能把“测试库无表”夸大成已经查证所有生产库无数据。本次判断依赖用户提供的未发布/未应用事实；若 Reviewer 后续拿出实际部署记录、旧表/写入路径或数据证据，再核实其与本功能的关系并重开影响评估。单纯坚持“可能有”不阻止新建流程继续。

## 必要验证

围绕当前新建流程验证：项目认可的可丢弃空库按实际迁移建表，再经真实新建入口写入并从同一库读回；检查本次约定字段、约束和直接消费者。迁移检查依项目实际 SOP 选用，不新增旧数据回填矩阵、不连接生产去证明猜测、不顺手修改发布策略。

本输入只要求裁决，评估中不实际运行迁移或修改代码；若后续实际执行，应先读取目标业务仓库及授权环境事实。

## 继续与完成判断

可以继续已确认的新建功能，无须等待 Reviewer 为假设写兼容方案。此 finding 的处理可结束，但不等于整个新建功能已经验收；其真实写入/读回和相关 CR 仍需有版本匹配证据。

## 使用的规则与矛盾

使用候选交付流程中的“先核实发布和数据事实”、`references/stages/review.md`、`skills/ts-code-review/SKILL.md`、`references/review-kit/database.md`、`references/review-kit/architecture.md` 与交付证据规则。数据库清单提到历史数据处理，是检查是否适用的提示；它本身不能推翻本例已提供的事实，未发现必须回填的具体规则依据。
