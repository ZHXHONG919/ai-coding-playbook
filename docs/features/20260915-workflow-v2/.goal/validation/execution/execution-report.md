## 事实与实际修复

- 原始测试只有一条，检查上传返回的 `required` 字段；原始测试通过，但不证明手动预览、询问补充或失败重试。
- 根因：`uploadImages` 将 `loading` 设为 `true` 后，成功和失败出口均不复位；`canPreview` 因此始终拒绝预览。
- 在 `uploadImages` 使用 `try/finally`，确保成功和失败都恢复 `loading = false`；保留异常向调用方传播、成功写入方案并询问补充的行为。
- 核对相关消费者 `dataReady`、`canPreview`、`preview`、`answerSupplement`。手动预览条件保持 `!loading && dataReady`，不额外要求补充结束。
- 自动预览将原来的真假值取反改为显式 `more === false`。依据用户“只有明确不再补充”约束，避免漏传参数、`null` 等被当作结束；正常布尔回答行为不变。样例没有浏览器调用方，实际 UI 参数契约未验证。
