# Goal 执行交接

将已确认需求转为可恢复执行输入。轻量改动直接实现，不因有 API / 数据库就建 Goal。Goal 创建和恢复统一使用本页说明的 schema 3。

## 开工前真正需要确定的事

- 已有实施授权；全部用户结果、非目标、交付与发布边界明确，不能只列首条路径。
- 每个结果说明入口、操作、对象/上下文、可观察结果和至少一种容易误实现的解释。涉及界面时按区块/动作指定当前有效来源，保留项和允许差异有依据。
- 先识别会影响后续实现的共享权限、身份、计费、状态等规则，并审查其必要设计；实际依赖其真实能力前先完成基础核验。已明确并核验的协议可供前端模拟开发，不能把未知业务语义写成假响应；具体边界见 `references/plan/task-breakdown.md`。其余工程任务可滚动细化。
- 当前路径事实与必要工具可用；局部未知有稳定协议、责任人和回收点。缺口可隔离不等于可以从最终交付中删除。
- 有确认原型时，按 `references/plan/task-breakdown.md` 保留本组完整前端体验先行的依赖及继续条件；接口契约基于领域设计，服务端任务注明承载职责，不能只列按钮对应的接口。前端体验是否完成以 `references/stages/review.md` 的门禁为准：现有记录里要有点完后的差异，不新增 Goal 状态。未通过前不把该组真实保存标成可开工，也不把代表页默认态写成可以复用布局。开工时的 `next_action` 只写第一段，并点明要打开的现有技能、留下的记录和停止条件。
- 一个 owner 对完整路径负责，文件和共享运行资源分工明确，独立验证/CR 可执行；结果清单不要求逐个同步 CR，相关使用过程可以合批。复杂方案沿用已有 design CR，不再要求同一批准。

## 最小执行包

在现有需求目录的 `.goal/` 中从 `templates/goal-v3/` 取模板：

| 文件 | 职责 | 何时创建 |
| --- | --- | --- |
| `goal.yaml` | 所有结果、当前决定/来源、依赖、最近要做的工程任务 | 开工；引用已有需求与原型，不复制整包文档 |
| `status.yaml` | 唯一执行索引：任务进度、有序核验记录、下一动作与缺口 | 开工；结果通过由证据派生，不另填一份通过表 |
| `runs/<ID>.yaml` | 一个版本增量的影响、验证、独立 CR 与证据引用 | 该轮核验时；不为每个技术任务建报告 |

快照及内容由脚本按需产生，不手写目录清单。已有工具、mock、风险台账直接引用；没有相关事项不生成空表。`tasks/README.md` 和 `tasks/Txx-功能名称.md` 保留按任务拆解模板形成的职责、具体行为、步骤及验证说明；已有 `tasks.md` 可沿用。Goal使用现有work引用文件/步骤、self_check引用检查项、depends_on承接步骤依赖；不要求整份功能文档对应一个工程任务，不改schema。产品及界面依据同时进入结果sources/decisions；当前采用的本地固定图片文件本身按负责状态逐项列入相关结果sources.path，不能只在work、采用说明或原型HTML中转引。检查器不递归跟随图片链接，交接时核对任务图片集合与结果来源集合，缺项先补齐，不改schema。进入 Goal 后不再维护一份相同任务状态。仅创建当前需要的文件。

## 组织与检查

1. 按 `references/plan/task-breakdown.md` 列全结果，展开首条真实路径及近期依赖；后续只展开所需工程步骤。
2. 将每项work/self_check回读到任务正文，核对自测入口、样本准备/状态生产者与所需能力在当步或前置步骤已可用，局部夹具检查不冒充真实生产。跨文档首次接线明确负责步骤，不让完整路径检查等待后继页面替换，不能仅凭depends_on无环宣布就绪。按任务拆解完成标准核对近期任务正文及界面原型/固定图片的精确位置，缺口只限制相关步骤；不把模板已填当实际可用。逐结果核对当前来源。两处相似按钮可能指向不同对象或页面，不能以技术任务的概括代替已确认动作。
3. `goal.yaml` 记录可解析的 Git 基线，`status.yaml` 初始化未完成状态。最终检查覆盖整个基线差异，包括新文件、删除和核验后修复。
4. 执行 `ruby <playbook-root>/scripts/check-goal.rb <goal-dir>`。脚本检查结构和版本一致性，不代替对开工条件及业务语义的判断。
5. 按 `skills/goal-execute/SKILL.md` 连续执行，具体字段与命令只在 `references/delivery/goal-v3.md` 定义。

用户主动修正时，先更新当前决定与受影响来源；旧证据保留为历史，不支持新约定。取消已承诺结果必须有用户依据，不能通过删结果来让检查变绿。局部能力不可用时推进可隔离工作，如实保留必需缺口，不自动重新开启产品问答。
