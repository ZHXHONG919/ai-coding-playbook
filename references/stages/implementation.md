# 实现落地阶段

> 已授权范围内连续实现、集成与必要自测。下一动作、接任、中文提示和运行资源分工统一见 `references/delivery/agent-delivery-flow.md`；核验触发只见 `references/stages/review.md`。

## 开始与继续

- 读取项目事实、当前结果及相关来源、授权与实际改动；不因换节点重复确认。仅讨论方案时不改代码。
- 默认当前目录与现有正常环境，不主动使用 worktree。Git 写操作按 `references/git-safety.md`；规则候选不应用时按 `skills/skill-maintenance/SKILL.md` 保护已安装源，不擅自改链接。
- 轻量工作不建 Goal；需要恢复时按 `references/stages/goal-handoff.md`，创建与恢复均使用 schema 3，执行入口为 `skills/goal-execute/SKILL.md`。
- 第三方能力按需读 `references/delivery/tooling-prerequisites.md`。首次核实必要入口、代表数据、权限和工具；不每步重复安装或做全量环境清点。真实 provider 验证属于范围且已有授权时执行，说明成本及证明边界。
- 在现有记录一次性保留主要成本来源、最早真实路径和集成余量；已有时间/token 约束直接沿用。按 `references/delivery/execution-evidence.md` 在已有边界比较进展与消耗，偏离时调整策略，不追加预算表。

## 实现、自测与集成

1. 主执行者推进完整路径；稳定且无冲突的工作才委派，结果返回后及时集成。共享资源由明确操作者安排，不因文件分离而同时重启服务或消费队列。
2. 先用能区分误解的样本核实实际生产者、转换与消费者。有确认原型的前端/API 工作按 `references/plan/task-breakdown.md` 先准备服务端开发态 Mock API，前端通过真实请求完成本组体验后推进服务端真实业务；已有能力直接复用，影响可行性的未知按有限探针提前验证。Mock 只证明已明确边界内的体验，不能替代真实能力。
3. 工程步骤滚动展开，普通自测通过即继续；技术任务 `done` 不代表结果验收。必要自测按 `skills/test-scope-analysis/SKILL.md` 从改变行为选择，已有足够证据时停止重复。
4. 服务端沿已定领域职责与依赖实现，核对规则的承载模块及所有相关入口；职责不清时补读 `references/plan/domain-design.md`，不直接按页面按钮堆逻辑。能力具备后逐步接回前端，首条真实路径用于校准事实；一组真实可用体验形成后合并独立核验。共享语义在实际依赖前定向审查，未涉影响的工作继续。
5. 修复后复核受影响行为。同类再发或自测与现场矛盾时先查实际执行系统与共同原因，避免继续修改未运行的代码。

## 有已确认界面时

实际打开当前动作/区块的采用稿，保持页面层级、打开与返回方式、对象上下文和控件关系；组件复用不得改写已确认交互。首个代表界面在相同视口、角色、状态与数据下校准，再扩展复用；不能用截图存在代替判断。无法校准的共享布局先不扩散，独立工作继续。

代表页面校准后继续完成本组约定的交互与状态，以真实点击、调用服务端 Mock API 及请求到达证据检查前端完整体验。通过后自主推进服务端真实业务，无须再等用户批准或新增一轮完整 CR；模拟证明范围和真实待验能力必须分开记录。

目标项目已安装 impeccable 时按问题选择 audit / critique / polish；用户认可调整优先于旧稿和通用审美。视觉、交互、业务分别用适当证据证明；只复查受影响状态，不为每次修复制造全套截图。

## 修订与交付

用户修订先更新单一业务决定及相关来源、受影响结果和派生契约；只暂停依赖旧约定的写入。已经授权的新要求不重复申请确认。共享规则变更沿生产者、消费者及恢复入口判断影响，旧证据保留为历史，不刷新摘要冒充重验。

恢复信息、任务进度和核验证据只存现有位置；非 Goal 可用对话或既有记录。收尾核对全部承诺结果、最终差异与当前运行状态，必需缺口未关闭不能宣布完整完成；准确区分代码验收、测试发布和生产发布，发布继续按已有授权与项目 SOP。
