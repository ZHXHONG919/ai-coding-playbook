# 发布检查阶段

> 目标：发布前确认代码、数据、配置、回滚和观测都准备好。

## 角色视角

发布检查阶段默认站在 Release Manager、SRE、数据负责人和业务 Owner 视角：

- Release Manager：确认分支、目标、窗口、发布顺序、阻断项和人工确认点。
- SRE：确认健康检查、日志、指标、告警、容量和回滚操作可执行。
- 数据负责人：确认 migration、回填、不可逆操作、备份、补偿和恢复策略。
- 业务 Owner：确认业务可接受风险、灰度范围、公告或人工运营动作。

复杂发布必须读取 `references/plan/role-lens.md`。

## 检查项

| 维度 | 要求 |
| --- | --- |
| 变更范围 | 本次发布包含哪些模块、接口、迁移、Job、前端页面 |
| 环境顺序 | 是否已按项目 SOP 先发布测试 / staging；生产发布是否等待明确人工通知 |
| 验证 | lint/typecheck/test/build/smoke 是否完成 |
| 数据 | migration 是否可重放，是否有回滚或补偿方案 |
| 配置 | 环境变量、provider key、开关、定时任务是否确认 |
| 兼容 | API/DB/前端状态是否兼容旧数据和旧客户端 |
| 观测 | 日志、错误码、任务状态、关键指标是否能排查问题 |
| 回滚 | 回滚步骤、不可逆操作、数据修复预案 |

## 输出

发布检查必须列出：

- Go / No-Go。
- 已通过项。
- 阻断项。
- 可接受风险。
- 不可逆操作和人工确认点。
- 测试 / staging 发布状态、smoke 结果和生产发布等待确认点。
- 回滚或补偿方案。
- 发布后观察项。

## 部署顺序门禁

- 用户说“部署”“部署下”“部署一下”“上线”“发版”“发测试”“发生产”，或说“已经 merge main，部署吧”时，进入发布阶段。
- Agent 必须先读取目标项目自己的发布 SOP / `AGENTS.md` / deploy 脚本说明。
- 默认先按项目标准流程部署测试 / staging，并完成 smoke 或验收记录。
- 没有用户明确通知或授权前，不执行生产发布；只能输出生产发布计划、阻塞项和等待确认状态。
- 即使分支已经 merge main，也不代表生产授权已经给出。
- 未指定环境的部署请求默认只允许测试 / staging；项目没有测试发布入口时，必须停下说明阻塞项，不得默认发生产。
- 生产发布必须同时满足：已有测试 / staging 发布结果，且用户明确说“确认发生产 / 可以部署生产 / 继续生产发布”等生产授权语。
- “部署下吧”“上线吧”“发版吧”不是生产授权；`merge main` 也不是生产授权。
- 生产目标的 `--apply`、生产域名、生产主机或生产 DB 写操作，在生产门禁满足前不得执行。
