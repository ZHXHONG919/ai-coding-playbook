# 场景规则：LLM 分析链路

## 适用

用于内容分析、样本学习、批量归纳、preset/topic/itemKey 生成、AI 审核建议等场景。

## 关键要求

- LLM 分析链路默认按复杂需求处理；进入方案前必须先做需求确认。
- 需求确认阶段必须收口：分析对象、样本来源、输出消费者、模型输出可信口径、候选与正式资产隔离、人工审核对象、失败重跑和产物留痕。
- 解释为什么不能一步完成，何处需要分层。
- 明确每层输入、输出、失败重试、是否落库、下游消费者。
- 区分样本输入、单条分析结果、批量归纳洞察、审核后资产。
- prompt 相关字段是场景专属，不是通用硬规则。

## 需求确认重点

方案阶段不能再悬空以下问题：

- LLM 输出怎样算合理：证据引用、schema 校验、维度归属、低质候选丢弃规则。
- LLM 输出写入哪里：候选区、建议区、预览工作区，还是正式资产；正式资产写入必须有明确审核或晋升条件。
- prompt 如何维护：关键 stage 的 promptKey、version、snapshot、active/draft/archive 状态和历史回放口径。
- 预览或审核对象是什么：只看结构化 key、看完整文本、看图片结果，还是看完整产物链。
- 历史任务如何追溯：输入快照、模型输出、parsed output、人工编辑、重跑记录和 provider 响应。

## 常见字段

| 字段 | 用途 |
| --- | --- |
| `prompt_version` | 标识使用的提示词版本，用于 A/B、回放和排查 |
| `prompt_snapshot` | 保存当次实际提示词，避免版本变更后无法追溯 |
| `raw_output` | provider 原始输出，用于排查和重新解析 |
| `parsed_output` | 结构化结果，用于业务消费 |
| `evidence_ids` | 结果引用的样本或证据，支持审核 |

## 注意

这些字段只在 LLM/AI 分析场景按需使用，不要污染所有方案。
