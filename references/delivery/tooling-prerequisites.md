# 第三方工具前置门禁

> 目标：任务需要访问第三方应用、网站或桌面工具时，优先使用稳定、可重复、不会抢占用户操作界面的结构化方式；开始执行前完成工具、安装、认证和权限准备，避免做到一半才反复控制浏览器或等待用户。

本文所说的 CLI 是“命令行工具（Command-Line Interface）”。CLI 通常是首选，但专用连接器、官方 API 或项目脚本已就绪且能力完整时，应直接复用，不为遵守形式上的“CLI 优先”额外安装工具。

## 使用时机

- 需要读取或写入第三方应用、网站、工单、表格、云服务或开发者工具。
- 需要使用飞书、微信开发者工具、GitHub、设计平台、数据库工具、云平台或类似外部系统。
- 需要批量读取、批量写回、上传、构建、预览、发布或状态查询。

## 工具优先级

默认按以下顺序选择：

```text
已安装的官方或项目既有 CLI
→ 专用连接器 / 官方 API / MCP
→ 项目脚本或受控自动化接口
→ 浏览器或桌面界面控制
```

- CLI 是第一选择，但不是为了形式强行使用。如果官方连接器或 API 能提供更完整、稳定的结构化能力，可以作为等价优先路径。
- 浏览器和桌面控制只用于前述方式无法覆盖的登录授权、可视化内容读取、真实交互和 E2/E3 视觉证据。
- 不得因为浏览器工具可用，就跳过 CLI、连接器或 API 探测。
- 不得默认控制用户正在使用的浏览器或桌面窗口；确需控制时先说明目标窗口、预计动作和停止点，优先使用隔离窗口或专用应用。

## 开工前工具清单

执行第三方操作前，先形成最小工具清单：

| ID | 能力 | 首选 CLI | 等价结构化方式 | 安装状态 | 认证状态 | 需要用户配合 | 界面控制是否必要 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| TP-001 | `<读取/写入/上传/预览>` | `<命令>` | `<连接器/API/脚本>` | ready / missing | ready / pending | none / login / scan / code / permission | no / visual-only / blocked |

检查至少包括：

1. `command -v <cli>` 或项目等价检查。
2. CLI 版本和目标项目要求是否兼容。
3. 是否已经登录、授权或具备目标资源权限。
4. 哪些步骤可以自动完成，哪些必须用户登录、扫码、输入验证码或批准系统权限。
5. CLI 能覆盖的能力边界；不能把“可以打开项目”误写成“可以读取模拟器视觉内容”。

普通短任务可以在执行说明中记录；复杂 Goal 的设计来源写入 `tasks.md`“工具前置清单”，执行状态写入 `.goal/tooling-prerequisites.yaml`，切片通过 `tooling_prerequisite_ids` 引用。不要为每个切片重复安装和登录。

### 敏感信息边界

- 工具台账只记录认证状态、动作类型、验证时间、工具版本/来源和脱敏后的 `Passed / Failed` 结果。
- 不得写入密码、验证码、多因素认证值、访问令牌、刷新令牌、Cookie、私钥、二维码内容、完整账号标识或完整敏感命令输出。
- `minimal_probe` 只记录命令/动作名称和结果，不保存响应正文；`user_action` 只记录 `login / scan / code / permission` 等动作类型。
- 敏感认证只在官方交互流程、系统钥匙串、凭据管理器或项目认可的安全存储中完成，不复制到 `.goal`、任务文档、日志或聊天摘要。

## CLI 缺失时的安装规则

用户授权开始任务、任务明确依赖某个 CLI、且没有已就绪的等价结构化方式时，CLI 缺失可以作为正常前置工作安装。已有连接器、API 或项目脚本完整满足能力时，将 CLI 标记为 `not_required`，不要额外安装。

- 只安装完成当前任务必要的工具，不批量预装可能用不到的 CLI。
- 优先使用项目既有安装脚本或系统已配置的可信包管理器。
- 优先安装到项目或当前用户范围，避免系统级和全局污染。
- 使用官方包名、官方发布源或项目锁定版本；记录安装来源和版本。
- 不执行来源不明的 `curl | sh`、远程脚本或未审查安装器。
- 不擅自安装需要付费、接受新许可、管理员/root 权限、修改系统安全策略或影响其他项目运行时的工具。

以下情况必须请求用户配合或确认：

- 浏览器登录、二维码扫描、验证码、多因素认证。
- 新增账号权限、组织授权、设备信任或敏感资源访问。
- 需要管理员密码、root 权限、系统扩展、证书、代理或防火墙变更。
- 安装来源不唯一、包名可能冲突、版本选择会影响其他项目。
- 安装或登录会产生费用、发布、通知或外部写操作。

用户配合完成后，立即验证 CLI 的登录状态和最小读取能力，再进入主任务；不要等到写入或发布时才发现权限不足。

## Goal 准备时机

Goal 采用 Gate 前集中准备：

1. Goal 交接阶段生成工具台账和任务/切片映射。
2. 主线程在 Goal Gate 前完成所有可自动处理的安装、版本和最小权限检查，并提前请求用户完成扫码、验证码或授权。
3. 当前首个业务切片引用的工具达到 `ready` 后，Goal Gate 才能标记 Ready。
4. 未来切片的凭据不要求永久有效，但待认证项、用户动作和最晚准备点必须登记。
5. Goal Execute 只消费和轻量复查已准备状态；认证失效时才回到工具准备，不在业务切片里首次安装。

## 界面控制边界

- CLI 能完成读取、写回、上传、构建、预览或状态查询时，不再为同一步骤控制浏览器。
- E2/E3 视觉问题仍需要等价运行态或视觉证据；CLI 输出不能替代视觉结论。
- 需要界面证据时，先完成所有 CLI 可做的准备和数据定位，再集中控制一次界面，减少登录、导航和窗口切换。
- 操作前告知用户将控制哪个应用；操作结束或等待用户配合时立即释放控制。
- 连续失败遵守证据驱动交付的尝试预算，不与用户争抢鼠标键盘，不无限重试坐标。

## 常见示例

### 飞书

- 优先使用项目既有或官方可信的飞书 CLI、专用连接器或开放 API，完成表格读取、父子记录展开、批量写回、附件上传和写后读回。
- 浏览器只用于 CLI 无法完成的首次授权、扫码登录或视觉版式确认。
- 不要为了读取多维表格数据默认接管用户浏览器。

### 微信开发者工具

- 优先探测微信开发者工具自带 CLI 或项目脚本，用于打开项目、构建、预览、上传和查询可结构化状态。
- CLI 不能替代模拟器内的视觉呈现、真实角色页面和交互验证；这些步骤按证据等级集中使用开发者工具界面。
- 需要扫码、登录、设备授权或上传确认时提前请求用户完成，不在任务末尾临时等待。

## 输出要求

开工同步至少说明：

- 本任务依赖哪些第三方能力。
- 首选 CLI 或结构化方式。
- 已安装/已认证、自动安装、等待用户配合的项目。
- 哪些步骤仍需要浏览器或桌面界面，以及原因。
- 安装来源、版本和是否影响系统范围。
