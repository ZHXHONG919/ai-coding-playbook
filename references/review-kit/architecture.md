# Review Kit：架构审查

## 关注点

- 模块职责是否清楚。
- 新抽象是否真的降低复杂度。
- 依赖方向是否合理，业务逻辑是否混入 controller/UI/infrastructure。
- 变更是否与现有项目模式一致。
- 是否为了未来假设过度设计。

## 高频风险

| 风险 | 信号 |
| --- | --- |
| 职责过宽 | Manager/Processor 类过大，方法服务多个目标 |
| 边界混乱 | UI 直接承担业务计算，controller 直接拼复杂逻辑 |
| 依赖反向 | 领域/业务层依赖具体 DB、HTTP、provider SDK |
| 过度工程 | 简单需求引入复杂模式、未使用扩展点 |
| 抽象不足 | 相同规则散落多处，字段归属不清 |
