# 方案规则：证据优先

Priority: CRITICAL

## 规则

技术方案必须先建立证据来源，尤其是用户要求“熟读项目”“参考旧方案”“不要照搬”时。

| 类型 | 来源 | 结论 | 可信度 |
| --- | --- | --- | --- |
| 项目事实 | 文件路径 / 模块 / API | 从代码或文档直接读到的事实 | 高 |
| 旧方案参考 | 文件路径 / 章节 | 可借鉴但需要改造的内容 | 中 |
| AI 推断 | 基于上下文推导 | 尚未被代码或用户确认 | 中/低 |
| 待确认 | 需要用户拍板 | 不确认会影响设计方向 | 待确认 |

## 要求

- 不要只说“我看了项目”，要列关键文件、模块或已有方案。
- 事实、推断、建议分开写。
- 没有证据的内容不能写成既定事实。
- 用户指出“和预期不符”时，优先更新证据表和决策表。
