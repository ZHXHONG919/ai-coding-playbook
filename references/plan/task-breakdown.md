# 方案规则：完整结果，滚动任务

> 前置确定要交付什么，详细计划只展开到当前路径和近期依赖。Goal 统一使用 schema 3；字段见 `references/delivery/goal-v3.md`。

## 先列全结果和共享基础

结果清单是范围边界，不能因技术任务尚未展开而漏掉已确认要求。每个结果列出 `owner`、当前约定与来源、依赖，以及能否被真实操作或消费：

| 结果类型 | 如何划分 | 必须说明 |
| --- | --- | --- |
| `user_result` | 一条完整用户路径，不按页面、文件或 API 拆成多个验收结果 | 入口、对象、动作、保留上下文、去向/状态、关键反例；各动作或区块的当前来源 |
| `shared_foundation` | 本次改变、且后续工作依赖其正确性的高风险共享规则 | 规则与消费者、失败传播范围、提前核验入口；如身份、权限、计费、核心状态、并发或迁移切换 |

复用成熟 API、数据库或既有权限不自动增加基础结果。不要把每个技术任务换名为结果，也不额外创建只负责汇总报告的“最终功能”；最终覆盖是整个 Goal 的收尾条件。

先核实关键入口、上游类型、消费者与真实数据事实，再确定依赖。所有已知高风险基础和外部条件前置识别；普通实现细节随代码事实展开，不能把影响全局的未知推迟到最后。

## 近期任务怎样展开

选一个输入可用、能尽早证明用户价值的结果，由同一 owner 持续推进。只展开当前路径、近期依赖及解除高影响未知所需的探针；后续结果保留约定、依赖和风险，接近执行时再补工程步骤。

每项技术任务保留：**ID、关联结果、实际工作和输出、依赖、必要自测、状态**。一个改动影响多个结果时全部关联，不要求一个任务只归一处；不为任务单独创建验收批次、逐任务 CR 或 `accepted` 状态。

必要自测先写清：

```text
改变的行为 → 最可能的错误解释 → 能区分它的样本 → 真实入口/观测点 → 预期
```

例如“任务卡能进入成品”不足以判错；应使用不同任务和多个结果，确认入口保留当前任务。依赖已有测试前先看样本能否区分错误；build、源码字符串或复制实现常量的断言不能替代行为证据。按风险选择最便宜且有效的方法，不因任务存在就补单测或重复跑同一套检查。

展开、合并或删除技术步骤只改变实现计划，不改变已确认结果。发现新的结果或业务规则变化时，先更新当前约定和受影响范围，再同步近期工作，不重写整个工程任务表。

## 前端完整体验先行，按功能组接通真实能力

有确认原型、且需要新增或改变前端/API 交互时，默认以一个完整页面或连续使用过程为功能组。先明确本组包含的动作、状态与返回关系，以及与其他组的稳定边界；不按单个按钮拆组来跳过完整交互，也不把全部独立页面捆成一个组。复用现有结果与任务说明，不新增分组状态文件。

```text
CONTRACT → FE_MOCK_LOOP → SERVER_CAPABILITY → MOCK_REPLACEMENT → INTEGRATION / QA
契约       本组完整前端体验   按领域能力实现       逐步替换接口模拟      真实功能验收
```

| 步骤 | 输入与工作 | 产物及继续条件 |
| --- | --- | --- |
| 契约与模拟接口准备 | 当前原型、需求、领域职责和真实上游类型 | 明确请求、响应、错误、权限、状态与副作用语义及页面映射；先提供可调用的服务端开发态 Mock API。后端设计与接口准备先行，真实业务逻辑后置 |
| 前端模拟 | 当前采用稿、已明确的契约与可调用的服务端 Mock API | 正式页面通过正常请求层发送真实 HTTP 请求，由服务端返回模拟响应；本组约定的浏览、编辑、保存、取消、返回及相关加载/空态/失败/权限/冲突状态可操作，并保持对象上下文 |
| 前端体验检查 | 运行中的本组页面、采用稿及判错样本 | 实现者确认本组交互、状态和原型还原，并核实请求确实到达服务端；缺项继续补齐。通过后自主进入服务端真实业务实现，不增加固定用户确认或独立 CR |
| 服务端与模拟替换 | 领域设计、接口契约及已可操作的前端 | 按领域能力及依赖实现；每个能力具备后接回前端，尽早完成第一条真实路径，不等本组全部后端写完才联调 |
| 真实验收 | 已替换模拟的完整操作及仍有效的证据 | 验证真实权限、持久化、副作用及最终消费者；相关使用过程按审查规则合批核验 |

完整前端体验以本组已确认范围为准，只覆盖相关状态，不穷举所有组合、不扩张视觉打磨。组 A 前端体验完成即可实现 A 的服务端，独立组 B 可以继续前端工作；并行仍须满足输入和资源边界。首个代表页面先校准再扩展；它通过不代表本组其余交互已完成。前端模拟通过只证明体验与接口消费方式，不证明真实业务能力。

默认由本组 owner 安排接口实现者在项目现有服务端提供开发态模拟 API，前端调用约定路由，不默认使用浏览器请求拦截或组件内假数据。一个 Agent 可以同时承担接口准备和前端实现，不为 Mock 固定增派角色或独立服务。用户或项目明确采用其他机制时遵从并记录依据；服务端暂不可用时保留接口准备缺口，先推进无依赖的界面工作，不能静默改用前端模拟并称本阶段通过。

模拟接口准备属于前端先行的前置工作：复用项目路由、参数类型、响应和错误约定，在接口后的数据/业务实现处提供可替换的模拟响应。覆盖必要状态切换和失败样本即可，不另造完整规则引擎；模拟数据与写入限于隔离的开发夹具，不产生真实业务副作用。用页面网络请求及服务端请求记录或等价观测核实调用到达，HTTP 成功只证明传输与响应，不能证明真实权限或业务能力。

模拟启用范围、真实替换负责人、替换点及清理条件写在已有记录中；负责人沿用本组 owner，明确接回后才能转交。随后保持约定的 API 路由、请求/响应和错误语义，逐项替换服务端内部实现，前端正常调用方式不变。开发态显式启用模拟，生产入口不得启用成功替身；真实逻辑失败不得回退到模拟成功。确需修改契约时同步模拟、前端消费者与真实实现，并复查受影响体验，不为迎合模拟数据改变领域事实。

### 何时调整顺序

- 已有真实能力可用时直接复用；成熟接口的局部改动、纯后端或无新交互的工作，不强制重做页面或引入模拟。尚无明确界面依据时先按方案规则补齐本次需要的依据。
- 影响可行性的外部能力、性能或新共享语义，允许在前端完成前做有限真实探针或必要基础核验。在已有计划写清要回答的问题、最小范围、停止条件和影响；不能借“尽早真实路径”提前展开全部常规后端。失败只阻止依赖该结论的工作。
- 模拟消费者只依赖已明确并核验的协议语义；尚未成立的权限、归属和状态规则不能靠假响应固化。真实共享基础仍按下一节在实际依赖前核验，探针通过不代替完整能力或最终验收。
- 用户或项目有明确实施顺序时遵从，并说明实际验证边界；不把默认顺序再变成一次审批。

路径写具体输入、应用入口、实际经过的边界、最终消费者及未经过的外部能力。例如“保存配置 → 预览读取 → 实际任务解析 → provider 请求含新值”，不能写成“接口 200”。目标环境、必要代表数据和工具能力尽早核实；付费/生产动作依已有授权执行，未执行保留缺口。

## 共享基础与隔离依赖

共享基础必须在消费者依赖其新规则前完成正式验证和 CR；内部相互依赖的实现步骤可作为同一基础中的技术任务，不为每一步再建基础。

消费者需要的是稳定协议还是已验证真实能力，要明确区分：

- 协议能独立确定时，限定输入输出、错误、状态和副作用。必要的协议核验通过后，可供消费者开发或模拟联调使用；真实集成仍依赖真实能力。
- 未解决的权限、数据归属、状态等语义不能用接口签名代替。不能把协议通过写成整个基础通过，也不能复用旧结果编号去证明一个被缩小的断言。
- 缺失能力在原结果下保留待完成工作、owner、解除条件、回收点及真实检查。生产代码不得返回伪造业务成功；TODO 和 mock 记录本身不算证据。
- 基础约定或实现改变时，沿生产者、全部消费者及恢复入口标出受影响结果；依赖旧基础的证据不再证明新基础下的行为。无关结果及证据保留。

具体隔离和阻塞处理见 `references/delivery/agent-delivery-flow.md`。

## owner 与并行边界

默认当前目录和现有环境，不主动创建或切换 worktree。结果清单用于防漏，核验分组按 `references/stages/review.md` 的连续使用过程决定，不按结果编号一一安排 CR。

同一 owner 贯穿准备、实现、集成和返修；需要换人时交接当前结果、采用依据、代码版本、缺口和写入范围。工程分工服从用户路径：要求同页弹层，就协调详情页与组件的写入，不能为分开目录改成独立页面。

共享契约、migration/Entity、核心状态或公共服务由一个 owner 收口；进程、端口、数据库、队列和运行配置的操作同样明确归属，不能只检查文件冲突。独立区块、已稳定契约的 adapter 等可并行，明确写入范围和整合责任。需要更新正在使用的约定时先同步受影响 worker；失联写入者未确认停止前不能接管其范围。正式核验使用固定版本，独立工作可继续。

## 记录、工具与完成标准

技术任务仅用 `todo → in_progress → done`；`done` 表示本步骤完成且必要自测通过，不表示用户结果通过。失败或阻塞保持未完成，并说明原因及可继续范围。

结果通过由正式检查证据判断。schema 3 在运行记录保存版本差异、改动到结果的映射、结果检查及独立 CR；当前有效性由工具结合历史记录推导，不手填一套结果通过状态。检查不能替代未完成的本次必需技术工作。收尾核对全部结果与最终增量，不因全部任务 `done` 或 CR 没有 finding 宣布完成。

证据等级、界面基线与证据门禁按结果和风险选择，方法见 `references/delivery/evidence-driven-delivery.md`。同一路径、角色和状态共享有效证据，不按技术任务重复截图。第三方工具按 `references/delivery/tooling-prerequisites.md` 共用一份能力/安装/认证清单；引用已有清单位置，不给每个任务重复安装、登录或建清单。
