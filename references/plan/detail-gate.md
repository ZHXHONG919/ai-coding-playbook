# 方案规则：可落地细节门禁

Priority: CRITICAL

## 规则

方案阶段不追求完整 DDD，但必须把轻量领域抽象落到字段、状态、流程、接口、任务和验收标准。否则不能进入实现阶段。

## 进入实现前必须具体到

| 细节 | 要求 |
| --- | --- |
| 概念 | 定义、边界、不属于什么、谁创建、谁消费、生命周期 |
| 字段 | 含义、归属、生产者、消费者、必填、索引、当前状态还是历史快照 |
| 状态 | 初始状态、事件、目标状态、失败状态、触发方、是否可重试 |
| 流程 | 每一步输入、输出、为什么需要、失败处理、下游消费 |
| 接口 | Request、Response、错误场景、调用方、权限或触发条件 |
| 页面 | ViewModel、操作、加载态、空态、错误态、审核/确认动作 |
| 边界与异常 | 超时、报错、重试、取消、幂等、并发冲突、部分成功、降级、补偿、人工介入 |
| 任务 | 输入、输出、涉及模块、依赖、验收标准、测试方式 |

## 反例

```text
实现内容池分析能力：
- 新增分析任务表
- 调用 LLM
- 生成分析结果
- 前端展示结果
```

这不足以达成一致，因为不知道概念边界、字段归属、状态流转、接口契约和验收标准。

## 合格口径

```text
分析任务只记录本次围绕某主题如何使用样本，不改写笔记自身质量。
analysis_task.status: draft -> running -> succeeded / failed -> reviewed。
analysis_result.evidence_note_ids 用于追溯结果引用了哪些样本。
POST /analysis-tasks/:id/run 只允许 draft/failed 状态触发，running 状态返回冲突错误。
```

## 边界与异常矩阵

复杂方案必须显式列出关键边界情况。至少覆盖：

- 输入边界：空输入、非法参数、重复提交、权限不足。
- 状态边界：不可触发状态、并发触发、已完成后重试、取消或失效。
- 外部依赖：超时、网络错误、第三方 4xx/5xx、限流、返回 schema 不合法。
- 异步链路：任务丢失、重复消费、部分成功、补偿或人工介入。
- 用户可见结果：错误文案、可重试入口、是否会产生脏数据或半成品。

每条边界必须说明处理策略和验证方式；如果不覆盖，必须写明原因。
