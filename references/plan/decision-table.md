# 方案规则：决策表

Priority: HIGH

## 规则

多轮方案讨论必须维护当前共识和决策表，避免每轮重新发散。

决策表记录的是业务、领域、架构或交付层面的选择，不是字段清单。不要把字段名、表字段、DTO 字段或任务项写成“关键决策”的结论，除非需求基线已经确认字段归属，并且字段表已经说明生产者、消费者和使用场景。

## 决策表格式

| 决策点 | 当前选择 | 理由 | 不确定性 | 状态 |
| --- | --- | --- | --- | --- |

## 决策与字段的边界

| 可以写在决策表 | 不应直接写在决策表 |
| --- | --- |
| `content_pool` 在 P0 承担主题学习空间 | 直接拍定 `content_pool.learning_goal` 字段 |
| 候选资产与正式资产隔离 | 直接拍定所有 candidate 表字段 |
| 预览审核通过后才晋升正式资产 | 直接拍定 promote DTO 字段 |
| prompt 按 stage 配置化和版本化 | 直接拍定 prompt 表所有列 |

如果决策会导出字段，先写成“工程映射候选”，再进入字段归属表：

```text
决策：P0 content_pool 承担主题学习空间。
工程映射候选：主题稳定 key、默认学习目标、主题边界可能需要存储。
字段归属判断：分别判断属于 pool/topic 层、task 层、preview 层还是配置扩展。
```

## 用户反馈处理矩阵

当用户提出多条评论时，先维护处理矩阵，再改方案。

| 用户评论 | 判断 | 方案修改 | 影响章节 | 状态 |
| --- | --- | --- | --- | --- |
| | 成立 / 部分成立 / 不采纳 | | | 已修改 / 待确认 |

## Change Sync

采纳用户反馈后必须同步相关文档。不要只更新当前正在看的文件。

| 变更来源 | 变更类型 | requirements.md | plan.md | tasks.md | ui-flow.md / prototype | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| 用户反馈 / CR / 新证据 | 需求 / 决策 / 字段 / 页面 / 任务 / 测试 | 需改 / 不需改 + 理由 | 需改 / 不需改 + 理由 | 需改 / 不需改 + 理由 | 需改 / 不需改 + 理由 | Done / Pending / Blocked |

判断口径：

- 需求口径变化：`requirements.md` 必改。
- 方案结构变化：`plan.md` 必改。
- 字段、API、DTO、migration 或实现边界变化：`plan.md` 和 `tasks.md` 必改。
- 页面流程、审核对象、操作矩阵、状态展示变化：`ui-flow.md` 必改；已有静态原型时同步 `prototype/`。
- 测试、发布、回滚变化：`plan.md` 和 `tasks.md` 必改。
- 不同步某个文件时，必须写清理由。

## 要求

- 每条用户评论都要有回应。
- 采纳时说明改了哪个模型、流程、字段或任务。
- 不采纳时说明原因和适用边界。
- 涉及字段时，必须说明字段归属表在哪里；不能只在决策表里出现字段。
- 如果用户评论指出“这个字段是什么用”，先回到字段归属和需求确认，不要继续扩展数据模型。
- 每次采纳反馈后，必须更新 `Change Sync`；存在 `Pending Blocking` 时不进入实现。
- 每轮末尾列“本轮需要确认”。
